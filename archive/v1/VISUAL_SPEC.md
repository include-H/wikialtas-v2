# WikiAltas 视觉语言冻结

> 状态:FROZEN(2026-09-10,产品方 × 总设计师确认)
> 优先级:与 DESIGN_V2.md 冲突时,以本文为准(仅限视觉、组件映射、首期范围三块)。
> 母本:飞书文档(产品方提供的飞书界面截图)。

## 0. 设计宪法

**凡是飞书有的,抄到像素级;凡是飞书没有的(作品树、题记、状态徽标、馆员面板),按飞书的视觉语法发明——做到让人以为它们就是飞书自己做的。**

100% 照抄飞书 = 直接继续用飞书。这个产品存在的理由就是补上那四样。

## 1. 界面四区(母本截图)

```
┌ 顶部导航栏(横向)
├─ 最左:全局导航栏
├─ 中左:文档大纲栏
└─ 中右:主文档内容区
     └─ 右侧:标签页侧栏(Altas｜关联与媒体(仅正文节点);收起态 = 右缘窄图标拉门)
```

### 1.1 顶部导航栏

- 左上:产品 Logo 与名称(占飞书「飞书文档」位)
- 面包屑:「用户 / 文档名」+ 小字「最近更新:x 小时前」
- 右上:蓝色「分享」按钮、眼睛图标(阅读状态)、锁图标、头像

### 1.2 全局导航栏(最左)

- 顶部搜索框(提示词「搜索」)
- 主导航(带图标):主页 / 媒体库建议 / 新建知识库(后两项为 WikiAltas 专有)
- (历史)飞书母本有「置顶文档」分组——2026-09-17 用户拍板:**置顶功能整体移除**
  (左栏「置顶知识库」粘性区与功能本体一并退役);首页只留「最近更新」
- 「我的文档库」列表:全部作品文档,当前选中项浅蓝高亮
- 底部:侧边栏折叠/展开控制

**WikiAltas 差异**(飞书没有、按飞书语法发明):

- 列表内容 = **作品树**:宇宙 → 系列 → 单作(parent 层级,可建/可移),
  节点带状态徽标 stub / draft / ready
- 不抄飞书的「云盘 / 知识库 / 智能纪要」——不存在的服务不装

### 1.3 文档大纲栏(中左)

- 顶部:当前文档标题
- 下方:编号目录树(1. 作品概览 / 2.1 基本资料 / 4.1 …),
  由正文 `##` / `###` 实时解析,点击滚动定位,当前章高亮

### 1.4 主文档内容区(中右)

- 信息栏:作者、修改时间;右侧**紫色「AI 共建」按钮** + 「...」更多菜单
  (更多里收纳:版本历史 / 回滚 / 删除,照抄飞书收纳法)
- 主标题
- 说明块(浅灰背景、斜体,对应正文开头的 `> 说明:`)
- 题记(渲染形态,见 §3)
- 九章正文
- **默认编辑态**(打开即编辑,可切阅读);编辑时题记按渲染形态显示,点击进入编辑

### 1.5 AI 助手(右侧标签页侧栏;收起态 = 右缘窄图标拉门)

> 2026-09-16 修订(用户拍板):悬浮窗改回**右侧标签页侧栏**——Altas 与「关联与媒体」
> 共用一栏 480px,用标签分开(关联与媒体标签仅正文节点出现,见三修订)。收起态 = 右缘 44px 图标
> 拉门(AI 图标 + 在途工单计数,正文节点加关联图标);点哪个图标就展开落到哪个标签。
>
> **为什么能改回**:09-12 改窗口的原因是 Semi AIChat 的 `nowrap` + `min-width: auto`
> 在窄栏集中爆发(工具卡撑破消息行、对话出横向滚动条);这一类窄栏渲染雷已被系列
> 前后端修复收口(对话层 min-width:0 连串、overflow-wrap、工具卡摘要截断)。侧栏
> 永不遮挡正文、不用挪位——窗口 Era 的核心取舍消失。
>
> 沿革(均为用户当面要求):09-10「右下角约 400px 悬浮面板」→「贴右侧可拖拽侧栏」
> → 09-12「可拖拽悬浮窗」→ 09-16「右侧标签页侧栏」。
>
> 2026-09-16 再修订:「关联与媒体」由两个旧标签(关联+媒体「原样收纳」)重造为
> 单标签四段结构(正片位/混杂内容/待确认/作品关系),正片位按介质收敛到单库;
> 上段「原样收纳」的表述作废。
>
> 2026-09-16 三修订(用户拍板):**媒体关联只属于正文节点(kind=work)**。
> 系列/宇宙是聚合层,右栏标签条与拉门都不出现「关联与媒体」;正文「…」菜单
> 同样不出建链项——建链只出现在正文节点,且只有正片位那一个库(介质→对应库)。
> 已存在的链仍可反哺/解除(按「链在」显示,不按节点种类)——历史遗留链留出口清理。
> 依据:一部作品只有一个载体介质,正片位天然单库;聚合层没有「本体条目」可言。

- 展开态:480px 定宽栏;顶部标签条(Altas｜关联与媒体)+ 右侧收起 chevron;
  最小化/展开是一条通路,状态记 localStorage(默认收起)
- 两个标签都**常驻挂载**(切标签/收起只是 CSS 隐藏)——收起不断在途工单的流
- Altas 标签即原面板:空态「今天有什么工作需要处理?」+ 输入框
  (提示词「发消息或创建任务... 使用技能 @ 添加资料」);工作态:折叠叙事流 +
  工具芯片(见 §4),**不是 JSON dump**;工具行只给人话摘要(JS 截断固定字数,
  **不摊原始 JSON 参数**),摘要全文与产物放进展开区
- 关联与媒体标签(仅正文节点 kind=work)四段,自上而下:
  ① **正片位**——只渲染介质对应的那个库(电影/剧集→Emby、游戏→GameAtlas、
  书/漫画→Komga;介质不明才三槽全显。作品只有一个介质,正片只可能在对应的库);
  空槽给「关联到 X…」入口
  ② **混杂内容**——role=mix 的链(OST/解析/预告…),不限条
  ③ **待确认**——扫库/检索产出的建议(关联/建档/忽略);**有内容时浮到最上**,
  空时收成一条细条(保留检索入口);检索支持自定义词(「预告」「OST」…)
  ④ **作品关系**——Altas 随工单建立的关系边(只读,箭头标方向)
  行契约:封面 + 标题 + 一行副信息,行末「⋯」菜单收操作(在库中打开/改判角色/解除);
  待确认行例外——主操作(关联/建档)按钮直显,⋯ 里只放「打开/忽略」
  正片级 vs 混杂级按条目角色分(Emby 看所在库角色,GA/Komga 恒正片级);
  去重按 source:entryId,无标题启发式
- 拉门角标:AI 图标 = 在途工单数;关联图标 = 待确认条数
- 收起后剩窄拉门;界面为干净文档,依然成立

## 2. 颜色纪律

- 全部颜色走 Semi token(`var(--semi-color-*)`);**禁止新写 hex**
- 选中态:浅蓝(Semi 默认 selected)
- **AI 唯一强调色 = 紫**(照抄飞书「AI 共建」按钮),只允许出现在 AI 元素上:
  右侧栏拉门/标签的 AI 图标、「AI 共建」按钮、AI 面板内部状态。除此之外界面任何地方不许出现紫色
- 禁止大面积渐变、发光、AI 光效、过度圆角

## 3. 题记(一级视觉组件)

- 渲染形态 = **书页留白**:居中、衬线体(Georgia / 'Noto Serif SC')、
  上下细分隔线、左上角引号装饰、右下署名;**无底色、无边框盒子**(不是普通引用块、
  也不是卡片)。2026-09-11 产品方按母本(无尽战争 Wiki)纠正:9a3ca2d 一度照本文
  的「淡底」二字做成了淡蓝底容器,是误读——「留白」指的就是不加底
- 观感样式已实现于旧仓库 `/root/Wiki/src/styles.css` 的 `.doc-epigraph`
  (配合 `/root/Wiki/src/views/LibraryView.tsx` 渲染逻辑),迁移进本仓库时
  用 Semi token 重写颜色,观感保持
- `:::epigraph` 围栏是唯一书写语法
- 题记是本产品唯一的"文艺"组件:严禁卡片化、严禁改造成普通 blockquote

## 4. 馆员(AI 面板的唯一人格)

- **定义:整个 Wiki 库唯一的一个 LLM,全权。** 用户说一句话,它自己判断
  要读什么 skill、查什么资料、改哪些条目、建哪些节点。
- **没有功能按钮菜单**(不搞"完善/扩写/总结"一排按钮);输入框 = 全部交互
- 工作过程 = **顺流时间线**(对齐 MiMo / dsh,2026-09-11 修订):
  叙事句(白字) + 弱化折叠条(「已读取 N 处 · 已检索 N 次」,展开看逐条工具行与检索计数) +
  **思考行**(模型的思考以「思考」折叠行展示,默认收起、展开看全文;进行中显示最后一句);
  叙事与工具按事件顺序只追加、不重排;不 dump JSON / 不裸铺工具参数
- 产物直接落进用户看到的同一份文档、同一棵树(revision 可回滚,无审批)
- 写 Wiki 按 `skills/wiki-writing`(9 章骨架、待核实、参考 ≥5)

## 7. 工作纪律(实现者必读)

1. 动手前先查 Semi 官方文档(Semi MCP / semi.design),禁止凭记忆 invent props
2. 组件优先 Semi;Token 优先;禁止 hex;禁止反向覆盖 `.semi-*` 内部类
3. 单文件 ≤300 行;业务不进 main.tsx
4. 改完必须过:前端 `npm run build`;后端 `go test ./...`
