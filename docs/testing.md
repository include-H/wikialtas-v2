# WikiAtlas v2 · 测试与验收

> **管什么**：怎么测、怎么验收、什么算"做完了"。
> **关联**：里程碑验收见 `README.md §4`；AI 评测用例见 `eval-cases.md`；技能写法纪律见 `skills.md §5`。
> **一条铁律**：**验收必须真跑**（真库 + 无头浏览器 + 行为断言 + 回服务端核对）；**不许只凭"构建通过"**。

---

## 0. 原则

1. **真跑优先**：v1 的 `scripts/e2e-ui.sh` 每一步都回服务端核对（草稿行 / 定稿版本 / 快照 / 写入事实 / 界面状态），并在应用脚本前挂错误钩子抓白屏 JS 错误——第一次跑就抓出"编辑器把空段落写成 `<br />`"的真 bug。**这种真跑 v2 要继承。**
2. **评测用例先行**：写或改技能/提示词前，先有 3–5 个**可复现**用例，每个写明"通过/失败"判定；**优先覆盖最易误用的场景**（该触发没触发、**不该触发却触发**）。
3. **保留无 Skill 基线**：同一任务①不给技能②给技能各跑一遍；**加了技能若没有明显改善 → 该技能该简化或删掉**。
4. **真模型调用要显式确认**：测试默认用 **mock / 副本库**；历史上有过误花额度的教训。
5. **不过就简化**：评测不过时**优先简化，而不是叠加新规则**。

## 1. 后端测试

| 层 | 手段 | 覆盖 |
|---|---|---|
| `domain` | **纯单测**（零 IO） | 标题归一化 · 排序键 · 介质规则 · 落位规则 · 重挂候选匹配 · 上下文预算裁剪顺序 |
| `store` | **`#[sqlx::test]`**（每个测试一个 PG schema，真库真迁移） | 树/建/排序键分配 · 定稿事务 · 草稿 lease · 乐观并发 · 快照/回滚 · 写入事实 |
| schema | **`tests/0001_init.smoke.sql`** 风格：约束冒烟（正例 + 反例，**每条反例校验报错类型** 23514/23505/23503，防"因为别的原因失败"被当成通过）；整体一个事务 + 末尾 `ROLLBACK` 不留数据 | CHECK / 唯一索引 / 外键 |
| 队列 | 集成测 | `SKIP LOCKED` 领取 · 租约过期回收 · 取消在工具边界生效 |
| 事件 | 快照/断言 | `response.*` 序号连续 · `output_item.done` 自足（丢了 `*.delta` 也不缺信息） |
| 提示词 | **`insta` golden 快照** | 每个 `section` 渲染（含"工具不在场返回空串"） |

命令（沿用 v1 心智）：

```bash
set -a; . .secrets/wikiatlas.pg.env; set +a
export DATABASE_URL="$WIKIATLAS_DB_URL"     # sqlx::test 要用它建临时库
cargo test --workspace                       # 单测 + 集成
cargo run -p wikiatlas-api                   # 起 127.0.0.1:8088，启动自动跑迁移
```

## 2. 前端测试

| 手段 | 覆盖 | 说明 |
|---|---|---|
| **vitest** | 纯逻辑：事件归约（`response.*`→会话模型）· 大纲拼接（分章替换）· 落位与匹配规则 · 失效/重挂状态机 · markdown 规范形 | v1 测试为零，v2 必补 |
| **playwright** | 真跑主链：`扫描 → 建档 → 写正文（流式）→ 定稿 → 反哺 → 手动制造失效 → 重挂`；每步断言 UI + 服务端状态 | 截图 + 行为断言 |
| **lint** | `eslint` + `tsc --noEmit` | v1 的 `lint` 只是 `tsc -b`，等于没 lint |
| **组件直觉** | 已知坑回归 | antd `<App>` 多包一层 `div.ant-app`（`height:100%` 链会断，表现"面板不触底"）· 点已选中节点是反选（空选必须保持当前节点）· 断点变→回默认宽度 |

`scripts/e2e-ui.sh`（v1 的验收脚本形态，v2 沿用并扩展）：**在应用脚本前挂 `page.on('pageerror')` 抓白屏**。

## 3. AI / 技能测试

| 手段 | 管什么 |
|---|---|
| **质量门（代码）** | 全部机械项（`prompts.md §3` 的 13 条）。技能怎么改都不影响它 |
| **快照测试** | 渲染出的技能文本进快照，改一个字都看得见 |
| **基准回归** | **18 篇成品 = 用户认可"写得好"的定义**；改技能/提示词后重跑生成，逐篇对照信息密度、证据落点、章节职责、语气有没有回退 |
| **触发纪律评估** | 记录 `read_skill` 调用，离线看"该读的读了没、不该读的没读"（`eval-cases.md §A`） |
| **成本纪律** | 触发真模型调用的测试要显式确认 |

**判据（按这个维度用，别按"单篇更长更全"）**：技能的价值是 **一致性 + 可校验 + 可迭代**。一条规则只在"能让产出一致/可校验/可迭代"时才留下。

## 4. 里程碑验收（对号入座）

每个里程碑的验收见 `README.md §4`；此处列"最低可交付证据"：

| 里程碑 | 最低证据 |
|---|---|
| M0 基线 ✅ | `cargo test --workspace` 全绿 + `scripts/e2e-ui.sh` 全过 |
| M1 媒体库进料 | 真库扫三源 → `library_manifest` 有数据 → 池子列出"有/无文档" |
| M2 建档与关联 | 池子点一条 → 树出节点 + 链 active；解链保留文档；撞名加介质后缀（截图 + 服务端核对） |
| M3 Agent 内核 | 真跑一次 run：流式正文投影 + 一个写工具 → SSE 到浏览器 → 草稿落库（副本库） |
| M4 写作与质量门 | 空库跑一篇同构正文 → 过质量门 → 定稿 → 快照生成 |
| M5 关系与综合 | 综合页挂关系 → 关联展示 → 索引页由宿主更新 |
| M6 Review 与体检 | 制造孤立节点/失效链/定稿未反哺 → 体检列出 → Review 可裁决 |
| M7 反哺与重挂 | 定稿 → GA/Komga 收到；停一个库条目 → 链 stale + 重挂候选 |
| M8 检索与问答 | 就库内容提问 → 回答带可点引用；好答案存成资料 |
| M9 对外与运维 | 外部 agent 走 MCP 只读检索；`pg_dump` 恢复；成本可见 |

## 5. CI / 本地一键

```bash
# 后端
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings

# 数据库冒烟
psql -h 127.0.0.1 -U wikiatlas -d wikiatlas -v ON_ERROR_STOP=1 \
     -f crates/store/tests/0001_init.smoke.sql

# 前端
cd frontend && npm run lint && npm run build && npm run test

# 真跑主链（需起 api）
bash scripts/e2e-ui.sh
```
