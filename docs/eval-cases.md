> 测试与验收的总体策略见 `docs/testing.md §3`；技能写法纪律见 `docs/skills.md §3 §5`；行为证据见 `docs/behavior-notes.md §10`。

> **产出质量基准**：`/root/Game_Wiki`（Atlas 按 `skills/` 技能集 + 联网检索生成的真产出；见 `README.md §3 D3`）。回归时以它为**质量目标档**——低于它 = 回退。
> 依据 `docs/skills.md` §5.1：**评测用例先行**、**保留"无 Skill"基线**、**评测不过优先简化而不是叠加规则**。
> 现状：系统还没开工（没有可运行的工单/技能加载器），所以这份用例先当**规格**用；两种跑法见下。

## 怎么跑

| 跑法 | 现在能做吗 | 做法 |
|---|---|---|
| **A. 子代理跑** | ✅ 能 | 给一个任务 + `skills/atlas/SKILL.md`（L0 目录）与技能库，让它**自己决定读哪几份**并产出；回收它的"读技能清单 + 自评" |
| **B. 系统跑** | ❌ 等开工 | 真挂到工单上：看 `read_skill` 调用序列 + 产出 + 质量门结果 |

## A. 触发纪律（最易误判的 8 条）

每条都写清**该读 / 不该读**——因为"不该读的读了"与"该读的没读"一样是失败。

| # | 任务 | 该读 | **不该读**（误触发才算失败） |
|---|---|---|---|
| 1 | 写一部具体作品的载体条目 | `wiki-write` · `wiki-skeleton` · 该介质的一个 `media-*` · `fact-check` · `prose-style` ·（要写题记则 `epigraph`） | `series-main`（对象不是系列）· `index-fields`（不写索引字段） |
| 2 | 目标节点是 `series`，写系列主文 | `series-main` · `fact-check` · `prose-style` | `media-*`（主文不按单作介质写）· `wiki-skeleton` |
| 3 | 任务要求写别名 / 关系 / 介质字段 | `index-fields` | `wiki-write`（不是写正文） |
| 4 | 写一部**续作**（同系列、讲新故事） | `wiki-write` · `wiki-skeleton` · 该介质 `media-*` | **`multi-source`**（只同系列不算） |
| 5 | 写一部**同源改编**（小说化 / 动画化 / 重制，讲同一段故事） | 上面那些 + **`multi-source`** | —— |
| 6 | 只改已有正文的一段 | `revise` | `wiki-skeleton`（不套整篇骨架）· `series-main` |
| 7 | 就库内容提问 | `qa` | `wiki-write`（不是写正文） |
| 8 | 只补写 / 重写题记块 | `epigraph` | `media-*`（题记与介质无关） |

**判据**：该读的都在清单里 ✓ 且不该读的一个没读 ✓。任一条不符 → 回 `docs/skills.md` §3 看该技能 `when` / `when_not` 是不是写含糊了（**先改规则，不要怪模型**）。

## B. 产出机械项（质量门预演，18 篇样本就是用它筛的）

对任一新产出，逐条查：

1. 标题以 `Wiki` 结尾；需要消歧时有 `（载体 / 年份）` 限定。
2. `:::epigraph` **有且仅有一个**；**块内无空行**（有空行 = 段级排布，应逐行交替）。
3. `## 1.`–`## 7.` 齐全、编号连续；末两章是「一句话总结」「参考资料」。
4. 章名按介质三档替换（影视 = 叙事与影像特色 / 图书 = 创作特色 / 游戏 = 玩法与结构特色）。
5. 第 6 章末节是关系简述。
6. 有 `>` 说明行（整理范围 / 来源 / 剧透 / 检索时间）。
7. 字段行是"一行一个字段、值里只有值"（没有判断句）。
8. 缺口只有 `待核实` 或整行删除（没有「据说」「广受好评」这类糊弄）。
9. 第 8 章（若存在）：一条一行、每条能指到出处、题记那处不重复。

> ⚠️ **第 9 条不能纯机械判**：实测里 `「…」；…` 既可能是"一个场景里的两句"（合规），也可能是"两个场景挤在一行"（违规）——判据是**"读者会不会把它当一件事去搜"**，不是分号个数。质量门最多能做"提醒"（如：场面项内含 `；` 就标出来让人看一眼），**别把它做成硬失败**。

## C. 无 Skill 基线对照（这条最关键）

**同一任务跑两次**：① 不给技能（只说"写一篇《X》的 Wiki 条目"）；② 给 L0 目录 + 技能库。

| 看什么 | 期望（给了技能更好） |
|---|---|
| 结构完整度 | 骨架 1–7 章齐全、章名按介质替换 |
| 信息密度 | 每段落到具体对象；没有"神作/天花板"式空话 |
| 事实纪律 | 缺口用 `待核实` / 删行，而不是编造或糊过去 |
| 题记 | 有出处、逐行交替、署名齐 |
| 该读的技能 | 只读相关那几份（不是全读） |

**判据（写死了）**：**加了技能若没有明显改善 → 该技能就该简化或删掉**；评测不过时**优先简化，而不是叠加新规则**。

> **【实测结论 · 2026-10】跑过一次对照**（同一作品《空之轨迹SC》）：**无技能那篇并不差**——310 行、13 段自创结构（还自列了「待核实事项」）、题记引 OP 歌词带出处、发售日冲突显式处理。
> 所以那条判据要**看清"改善"是哪个维度**：
> - 技能**没有**让单篇写得更长更全（模型本来就会写）；
> - 技能给的是**一致性 + 可校验 + 可迭代**：19 篇同构（跨条目可预期）· 机械项可被质量门自动查 · 规则改一处、全部产出跟着变（基线是"每次自创结构"）。
> → **判据按这个维度用**：一条规则只在"能让产出一致 / 可校验 / 可迭代"时才留下；对"单篇质量"没有可测贡献的规则，删。

## E. 形态覆盖清单（"忘了一个形态"就加到这里）

基准语料要覆盖的**形态**（不是题材）——每加一篇样本，先看它补的是哪个空格：

| 形态 | 现有样本 |
|---|---|
| 单作（新作 / 老作） | 007（新作）· 仙剑1（老作） |
| 续作（同系列、讲新故事） | 仙剑2 · 空之轨迹SC |
| 系列一员但**剧情独立**（跨子系列不延续） | 使命召唤：无限战争 |
| **同源改编**（小说化 / 动画化 / 重制，讲同一段故事） | 你的名字（小说化）· CLANNAD（动画←游戏） |
| **上下集**（同一段故事拆两部） | 复仇者联盟4 |
| 多季长篇（按季分节） | 紧急呼救 |
| 连续多卷（一篇 + 2.5 分卷表） | 猎魔人 |
| 连载超长（网络小说） | 斗罗大陆 |
| **合集产品**（把之前几代打包装成一个产品） | 🆕《光环：士官长合集》（见 `skills/atlas/references/samples/游戏/`） |
| 题记四式 | 引用式（16bit / 上古卷轴）· 场景式（007）· 诗句式（仙剑1）· 外部引文（你的名字 引和歌） |

**判据**：新形态第一次出现时，**要么技能里已经写明怎么处理，要么就暴露成一个规则缺口**——这正是这份清单的用处。

## D. 实测最易出问题的三处（回归时重点盯）

1. **`multi-source` 的适用边界**：容易按"同系列"误触发（已收窄 `when`，但要看真实效果）。
2. **`prose-style` 的触发时机**：它是"末段收尾"技能，容易被读得太早、或被漏读（`when` 已放宽到"任何写或改正文"）。
3. **引文门槛的两档**：题记与第 8 章走"能指到出处"档，正文走出去 `fact-check` 的档——**混用会出现"要么不敢引、要么乱引"**。
