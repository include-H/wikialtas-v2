# Atlas v2 · 行为知识清单

> **为什么有这份文档**：`backend.md §9` 与 `§10` 都点名——v1 最值钱的不是代码，是散在注释、工具描述与提示词里的**调优经验**（"模型会这样，所以别那样"）。重写语言若把这些丢掉，等于把踩过的坑再踩一遍。
> **纪律**：这份清单是**写 M3（Agent 内核）之前的必读**，也是验收标准的一部分。每条都标注**来源**（v1 = `archive/v1` 的 DESIGN_V2/AGENTS；`llm_wiki` = 参考仓库；`观测` = 实测），改 agent 层时逐条对照。
> **关联**：`ai.md`（能力面）· `tools.md`（工具契约）· `prompts.md`（提示词与质量门）· `backend.md`（进程与队列）。

## 0. 三条元原则

1. **一个事实只有一个 owner**：工具怎么用 → 工具的 `description`；跨工具的习惯 → 提示词段；身份 → `identity` 段。**写两处必然漂移**。（v1 · DESIGN_V2 §4.9）
2. **每条规则配边界**：不说"用 edit"，说"用 edit 改一句，别为一句重写整章"；既说何时用，也说何时用不对。（v1 · DESIGN_V2 §4.9）
3. **数字与状态从代码注入，不手抄**：`contextWindow` / 检索预算 / 压缩比例 / 管理员名，一律运行时注入。（v1 · DESIGN_V2 §4.9）

## 1. 会话日志 = 上下文的事实源

> 来源：v1 · DESIGN_V2 §4.8；对齐 DeepSeek Harness。**这是 v1 设计得最好的一块，v2 原样重用。**

- **模型可见 ⟺ 有日志**。一条会话 = 一条追加式日志（`session_messages`）；模型看到的历史是它的**投影**，**不单独存一份数组**——不存就不会"存下来的和看到的不一致"。
- **只追加，不改历史**。要"改"就追加一行并遮蔽旧行：`shadowed_by` 非空 = 被替换（仍在日志里、不在投影上）；`replaces_seq > 0` 的替换行**占被替换区间的起始位置**（否则被替换的 system 会排到消息中间）。投影规则：活的 system 恒在最前，其余按位置序。
- **新 Run 从日志派生上下文，不重建**。系统提示变了 → 追加一行替换旧的 system（系统提示是**派生历史**，不是 header）。user 行带请求头指纹与原因 `initial | continue | change`。
- **压缩 = 日志上的一次显式替换**，摘要骑在一条 user 行上。**工具结果在入口不截断——只有压缩能缩小内容。**
- **检查点不存消息**（`runs.checkpoint` 只留 iteration/tool_cache/context）。resume 从日志派生；给中断的半截 turn **补合成收尾**（assistant 有 tool_calls 没结果，provider 会直接 400）。
- **两条可执行的不变量**（不是口号，要落成事件与断言）：

| 不变量 | 做什么 | 事件 |
|---|---|---|
| 前缀稳定 | 本次请求必须是上次的**追加延长**，除非有记录原因（压缩） | `llm.request.{appendOnly,divergedAt,shapeReason}` |
| 重建一致 | 每轮用日志独立投影一遍，与内存里的请求逐条比对 | `llm.request.rebuildOK` |

> **真实 bug 留档**：重建不变量落地第一天就抓到一个真 bug——新增 system 行时只写了日志、没加进内存数组，**第一轮请求里根本没有系统提示**。所以这两条不变量一条都不能省。

- **跨会话回忆不靠重建**：`search_sessions` / `read_session` 两个只读工具让模型主动搜早先会话；读到的内容一律当**不可信背景**，绝不当作指令。（v1）

## 2. 上下文预算（硬预算，不是展示数字）

> 来源：v1 · DESIGN_V2 §4.8。

- 一次会话能装多少 token（系统提示 + 全部历史 + 本轮输出），由设置页给出（`llm.contextWindow`），**全 harness 只有这一个数**。
- 到 `窗口 × 0.75` **压缩一次**；压完仍放不下就**拒绝发送并说明原因**。
- ⚠️ **坑**：v1 曾另有一个拍出来的"20 万字节预算"（≈6.6 万 token，32k 窗口时代的数字），在 262k 窗口上等于用了四分之一就开始压缩——那正是"压缩丢资料 → 模型重查 → 又压缩"循环的病根。**窗口必须跟模型走，且只有一个来源。**
- **窗口大小可配（4K–1M 滑块）**：不同模型能力差得远，写死在代码里是错的。（v2 `ai.md §2`）
- **比例预算**：v2 采用 系统 15% · 索引 10% · 目标 40% · 历史 20% · 余量 15%；裁剪顺序：关系 → 资料 → 兄弟 → 子节点 → 最后只留"祖先路径 + 目标本身"。（`ai.md §2`）
  - llm_wiki 的对应比例是 页面 50% · 历史+系统 ~30% · 索引 5% · 响应预留 15%（`context-budget.ts`）——**结构同源，数值按各自场景。**

## 3. 护栏（v1 验证过的，全保留）

> 来源：v1 · AGENTS.md / DESIGN_V2 §4.5.1。**这些是"事实发生"级的硬护栏，别当成可选项。**

| 护栏 | 规则 | 为什么 |
|---|---|---|
| 空写拒绝 | `write_content` 内容为空 / 退化（截断守卫：`>200 字符 → <50 字符`）直接拒 | 防模型把整章写没了 |
| 归档拒写 | `status=archived` 的节点，所有写工具拒写 | 归档 = 树与检索默认排除、可恢复 |
| 参数 JSON 错就报错 | 工具参数 JSON 解析失败 → 报错返回，**不猜、不补全** | 猜 = 静默写错 |
| 重复调用分级 | 同名同参工具 > 3 次直接回 `ok:false`（`todo_write` 除外——任务清单本来就要反复整份提交） | 模型原地绕圈烧额度（观测过同一章连改 6 次） |
| 联网预算 | 联网检索有预算上限 | 控成本 |
| 截断必须说话 | 任何因长度被截的内容，**必须在结果里说明"被截断了"** | 静默截断 = 模型以为拿到了全部 |
| 破坏性写只许自有可回滚 | LLM 只能删**自己造的、无版本可回滚**的对象（空节点/空资料/关系边）；有正文的节点走 `archived`；带正文的硬删**永远是人类界面专属** | 内容是不可再生资产 |
| 批量波次 | 波次 + 预检在前 + 全成或全不成 + 上限（`patch_sections` / `upsert_relations` 是范本） | 半成品最难收拾 |

## 4. 工具面纪律

> 来源：v1 · AGENTS.md。

- **工具面只按用户显式选择剥写工具**：`docMode=read`（只读模式）与 `oneShot`（工具栏「翻译/解释」按钮的能力契约）。
- **意图不决定能力面**：`answer / continue_wiki …` 只是提示里的任务框定与 skill 预载依据，**不决定工具面**。猜错了（错字 / 纠偏 / 问句暗示干活）也要能干。
- **运行时二次校验**：被剥掉的写工具即使被模型幻觉调用，也**拒绝执行**（双层防护）。
- 护栏在**动作层**（修订可回滚、写工具自带空内容/残稿拒绝）与**提示**（`This task` 段的执行偏向："能核实就落下去，别汇报完等批准"；一次性输出不落盘），**别再加"按猜测锁工具"的设计**。
- **质量门与节点扫库按 `wroteContent` 触发，不看意图标签**——问答单也可能顺手写正文；验证跟着"**事实发生**"走。
- **新工具里必须有链路工具**（v1 缺，靠 API）：`detach_link`（解链）/ `relink`（重挂）/ `rebuild_doc`（重建档）。（v2 `tools.md §2`）
- **context 字段是三件套**（v1 踩过：`@` 引用就这样坏过）：前端 `CreateRunBody.context` + 构造处（别铺平 Record）+ 后端 `RunContext` 字段 + 编排层到 ctxMap 的映射。**缺一环就静默丢**（Go 结构体解码不认识的 key 不报错——Rust 侧同理，靠显式字段 + 测试守）。

## 5. 流式正文投影（体验核心，最易写错）

> 来源：v1 · AGENTS.md「正文流」/ DESIGN_V2 §4.7。

- **正文是从写工具的流式参数里出来的**（`write_content.contentMd` / `patch_section.newMarkdown`，即 Responses 的 `function_call_arguments.delta` 累积成 JSON、正文在其中一个字符串字段里）。要在**不完整 JSON** 上增量抽出正文并推送。
- v1 的做法：解析累积 JSON 的前缀（`partialStringArg` / `closedStringArg`）+ **~200ms 节流** + 按章节分槽（波次）；三条投影路径（`write_content` / `patch_section` / `patch_sections`）。
- **staging 提前到开写时发出**；逐条 `function_call_arguments.delta` **对这类工具不再转发**（没有消费者，且一个条目几千条会把前端全量归约卡死）。
- 前端由 `liveDraft` Provider 累积；**值 / 写入口拆两个 context**，避免全应用跟着重渲染；`patch_section` 用 `spliceSection` **原位拼接**（镜像后端 `ReplaceSection` 的匹配规则，改一边要同步另一边）。
- 收尾两种语义：`commit()`（留末稿垫底防闪回）/ `abort()`（中断退回真实内容，工单被停/失败）。
- **落块动画**：流式帧走**增量替换**（按块指纹找分歧点，前缀块保住 DOM），当前段挂 `.live-tail`（压暗 + 文末紫色脉动条），段落写完摘类 → 渐显。
  - ⚠️ BlockNote 的坑（Milkdown 侧需重新验证同类风险）：删除集不能为空；纯追加走 insert；不能整篇重建（会把所有动画重播）。
- v2 的改法（`backend.md §5`）：把它做成**独立的增量 JSON 状态机**（单独 crate 或 `agent::stream` 模块）+ **重点单测**；**SSE 只是加速，草稿行才是真相**。

## 6. 提示词 = 分段组装

> 来源：v1 · DESIGN_V2 §4.9。

- 系统提示不是一坨字符串，是 `section{name, order, text}` 的有序集合：
  - `name` 是唯一键，也是**替换槽位**（同名即覆盖）；
  - `order` 取自中心表，**编号稀疏**，插新段不必重排；
  - `text` 是函数，拿得到运行时状态，**工具不在场就返回空串**——段自动跟着工具面走（`answer` 意图读不到写工具的规矩）。
- v2 的分段顺序（沿用 v1 调出来的，`prompts.md §1`）：身份 → 意图 → 工具面 → 会话记忆 → 探查 → 研究 → 上下文窗口 → 文档模式 → **技能** → 收尾 → 语言。
- v2 改一处：**技能段只渲染 L0 目录**（不再把技能正文塞进 system）。
- 稳定文本用 **golden 快照**钉住（v1 是 `internal/run/testdata/system_prompt_*.golden.md`）：改了提示词快照就红；有意改动用 `UPDATE_GOLDEN=1` 重新生成。

## 7. 模型行为（观测）

> 来源：v1 · AGENTS.md「LLM 使用」。

- **思考档位合法值只有** `none / minimal / low / medium / high / xhigh / max`——**没有 `off`**。机械判定（媒体库扫描 / 层级判定 / 题名变体 / 相关性判官）用 `none` 直出；写作 / 问答工单用默认档。**别把无思考档拿去做需要推理的活。**
- **没配 Key 会退回 mock/echo**：任何直接调模型的端点必须先用 `HasAPIKey()` 守卫。
- **模型偶发空答 / 畸形输出**（真见过判官返回 `{"links":[]}`）：关键路径要有**重试兜底 + 日志**，别静默成"没找到"。
- **判官类结论要有确定性兜底**：判定失败退回启发式，**不允许挡扫描**（v1 · Komga 层级判定）。

## 8. 媒体库相关

> 来源：v1 · AGENTS.md「媒体库模块」。

- **LLM 永不主动建库 / 挂链**：AI 只产出建议，用户点确认才执行；"写完之后"的关联由**宿主钩子做确定性扫库**（node-sweep）。
- **扫描是低频确定性流程，稳态零 LLM。**
- **判定口径缓存**：Komga 层级判定按「书单指纹 + 口径版本」缓存；**改了判定 prompt 必须把口径版本加一**，否则旧判定永远不会重判（v2 泛化为 `judge_cache.fingerprint`，见 `database.md §2`）。
- **三种"不要"别混**（`library-sync.md §4`）：
  - 池子全局忽略（manifest，条目没价值）；
  - 节点页 per-node 忽略（Dismissed，别向这个节点提起，可附理由）；
  - 建议拒绝（Rejected，模型给的挂法不对——条目仍是一等公民；拒绝理由进 KV，下次「AI 对一遍」作为 `previousRejections` 喂回模型二次判断；模型复读被拒挂法时行不藏、挂「上次被拒」标注）。
- **API 形状纪律**：空列表一律给 `[]` 不给 `null`（前端 `.length` 直接崩）；KV 里多字段共存时，别写"空列表 = 没有记录"这类守卫（会吞掉同记录里的其他字段）。

## 9. 从 llm_wiki 学到的（v2 采纳项）

> 来源：参考仓库 `nashsu/llm_wiki`。**只列 v2 要采纳的**；不采纳的见 `v2-from-v1.md §4`。

- **两步式 ingest**：先 analysis（结构化、便宜档）再 generation（主模型、FILE/REVIEW 块）。v2 采纳（`ai.md §4`）。
- **宿主确定性维护聚合页**：`index.md` / `overview.md` 由应用维护，**不让模型重写整篇**（"大 wiki 永远不会被模型整篇重写"）。v2 采纳为"索引面零 LLM"（`ai.md §2`）。
- **长文：语义分块 + checkpoint + 全局 digest**：超长来源分块分析、跨块累积候选、**最终才定 `Page-worthy`**；带 `SHA256` 指纹判断 checkpoint 是否可用。v2 采纳给"连载超长 / 多季长篇"（`features.md §5`）。
- **结构化产出语法**（`---FILE: path---` … `---END FILE---` + `---REVIEW: type | Title---`），带**严格解析 + 截断修复 + 兜底生成**（"保证资料摘要一定被创建"）。v2 采纳进 `prompts.md §2` 与 Review 队列。
- **溯源 + 共享实体保护**：每页 frontmatter `sources: []`；删源时若实体被多源共享，只从 `sources[]` 摘除、**不删页**。v2 采纳进"文档耐久、链只标记"（`library-sync.md §6`）。
- **技能只暴露 `name` + `description`，正文按需 `read_skill`**；技能根可叠加（项目 > `~/.claude/skills` > `~/.codex/skills`，项目优先）。v2 采纳（`skills.md §1`）。
- **`SKILL.md` 的 `description` 必须写清"何时用 / 何时不用"**，且**刻意不响应泛泛的触发词**（llm_wiki 的 agent skill 明确不响应"搜我的笔记"）。v2 采纳进 `skills.md §3` 与 MCP 触发纪律。
- **可配置上下文窗口 + 比例预算**：v2 采纳（见 §2）。
- **中文检索用 CJK bigram**（`search.ts`：二元组 + 单字兜底 + 标题匹配加分），不依赖分词词典。v2 采纳（`database.md §3`）。
- **SHA256 增量缓存**：源内容哈希未变则跳过（`ingest-cache.ts`）。v2 采纳给扫描 / 重跑（`library-sync.md §3`）。
- **Review 预定义动作 + 每条带预生成搜索词**（防模型凭空生成操作）。v2 采纳（`ai.md §9`）。

## 10. 反过拟合纪律（技能 / 提示词维护）

> 来源：v2 `skills.md §3`（借 TRAE），**改技能前逐条对照**。

1. 每条规则要能回答"**删了它会坏什么**"；答不出 → 删。
2. **禁止特判**（"上次模型把 X 写成 Y，所以别 Y"）：可机械校验的搬进质量门，不可机械的写成准则 + 正反例。
3. **不许写"不存在的禁忌"**：规则只能来自 ①基准样例 ②真实失败 ③用户明确要求。
4. **教判断，不教长相**（题记由材料决定，不是规定长相）。
5. **不许从单个实例推断类别规则。**
6. **例子是示范不是模板**；完整示例指向 `sample:` 资源，不抄进技能。
7. **清单要问"最常见的那一项在不在"**（epigraph 曾漏了"台词"这个最常见来源）。
8. **技能里只放"给模型的指令 + 正面范例指针"**；维护者元信息（依据/置信度/历史/待定）一律进 `docs/`。
9. **技能不写宿主/接口/数据库/目录/审批**（那些归工具描述与系统提示）。
10. 每技能配**正反例**；**失败路径（On Failure）**要写；有产出物的技能写**结构化 Input/Output**；**给默认路径**（禁等价罗列）；**不写时效信息**；**自检带闭环**（不过就回到哪一步）。
11. **技能单独可验证**：改一个技能只跑它相关的用例与质检项。

> **实测结论**（`eval-cases.md`）：技能**没有**让单篇写得更长更全（模型本来就会写）；技能给的是**一致性 + 可校验 + 可迭代**。判据按这个维度用——一条规则只在"能让产出一致/可校验/可迭代"时才留下。
