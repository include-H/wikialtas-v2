# WikiAtlas v2 功能清单（讨论稿 v0.2）

> **基准**：`nashsu/llm_wiki`（核心主张：知识库是**被持续维护的产物**，不是每次现挖 RAG）
> **布局蓝本**：飞书云文档三面板　**前端**：Ant Design X　**后端**：Rust　**数据库**：PostgreSQL
> 本稿已并入：核心链（扫描 → 一键建档 + 关联）· 反哺（WikiAtlas 为真源 → GameAtlas / Komga）· 失效链（「来源已失效，请重新挂载」）
> 决策冻结表见 `README.md §3`；v1→v2 的「去/留/改」见 `v2-from-v1.md`；媒体库子系统见 `library-sync.md`。

## 0. 定位与核心链

**WikiAtlas = 媒体库的文档层。** 它由 GameAtlas 的 Wiki 能力衍生而来，把它从"只有游戏"扩到影视/漫画/书；库里的**一个条目对应一篇 wiki 文档**；**WikiAtlas 是真源**，把最新文档反哺回库。

**核心链**（这就是这个应用存在的理由，缺一不可）：

```
① 扫描        三源 → 条目清单（宿主，零 LLM，纯确定性）
② 池子        列出"库里有哪些条目 + 哪些还没有文档"
③ 建立文档    人点一次 → 原子产出【树里的节点】+【条目↔节点 的链】
④ 写正文      模型写 → 草稿落库 → 定稿（草稿/定稿/快照）
⑤ 反哺        定稿 → 推回 GameAtlas / Komga（Emby 只读，不参与）
⑥ 失效与重挂  库里条目没了 → 链标记失效 +「重新挂载」；文档永不动
```

三条硬规则（不可违背）：

1. **扫描与建档不需要模型**。模型的位置在 ③ 之后（写正文、维护），不在"该不该建"这个判断上。
2. **关联靠身份，不靠标题**：`source + external_id`（Emby item id / Komga series id / GA public_id）。标题会变、会重名、会分版本。
3. **文档是耐久物，链是可替换的指针**。链失效只标记，不删链、不删文档。

## 1. 扫描与清单【宿主 · 零 LLM】

- 三个源客户端：GameAtlas（管理员会话 cookie）· Emby（`X-Emby-Token`，只读）· Komga（`X-API-Key`）。
- 清单条目字段：身份（source + externalId）· 标题 / 副标题 / 别名 · 封面 · 年份/发行日 · 容器（库 / 系列）· `kind`（tv|movie|game|book）· `format`（comic|novel）· 条目 URL · extra（GA 系列成员等）。
- **容器语义分两类**：GameAtlas 的 series、Komga 的 series = **作品系列**（可以当父节点）；Emby 的 library（番剧/电影/内地剧）= **库**（拿库名建节点毫无意义）。
- 扫描周期（可关）+ 手动扫描；**忽略**：单条忽略 / 整组忽略（区分"我不想要这个文档"与"这个条目本身没价值"）。
- **与链比对**产出三种事件：`新增`（库里新出现）· `消失`（→ 链失效，见 §4）· `变更`（标题/年份/容器等元数据变了 → 体检项：文档里的信息要不要跟着改）。

## 2. 建档与关联（核心动作）【我们 · 不需要模型】

- **落位规则**（一个条目 = 一篇文档）：
  - 容器是**作品系列** → 文档建在该系列节点下（系列不存在则建）；
  - 容器是**库**（Emby）→ 文档建在顶级（或用户指定的父节点）；
  - 子标题默认 = 条目名；**只有与父节点同名或与已有兄弟撞名时**才加介质后缀（`《X》→《X（剧集）》`）。
- **原子性**：节点与链在同一事务里创建；失败不留孤儿节点。
- **批量**：整组 / 多选一键建档（有上限，因为下游写正文要花钱）。
- **链的属性**：`role = 正片 | 混杂`（正片=本体级；混杂=OST/预告/解析）· `linked_by = manual | pool | archive | sweep`（谁建的，可追溯）。
- **撤销**：解链（保留文档）／删文档（同时删链）。

## 3. 反哺【新 · WikiAtlas 为真源】

**能力矩阵**（决定每条链能反哺什么）：

| 目标 | 通道 | 能写什么 | 方向 |
|---|---|---|---|
| **GameAtlas** | `PUT /api/games/{id}/wiki` | 正文 + 摘要 | 双向（我们写回去） |
| **Komga** | `PATCH .../metadata` | 条目 metadata 摘要 | 双向（我们写摘要回去） |
| **Emby** | —（只读） | 不可写 | 单向（只读它） |

- **时机**：**定稿时自动推送**（定稿是唯一"内容变了"的确定性事件）+ 手动「重新推送」。
- **语义**：这几个字段由 **WikiAtlas 独占写**，以**最新定稿**覆盖；不合并、不做双向 diff。
- **同步状态**（每条链 × 每个目标）：`synced_ver`（推的是哪一版）· `status`（待推/已推/失败）· `message`（失败原因）· `synced_at`。→ 失败可见、可重试，且能回答"库那边是不是这篇的最新版"。
- **Komga 摘要适配（已冻结）**：取正文首个非说明非题记段落、去 markdown 标记、**上限 500 字**、超出加 `…`；实现期以实测字段约束为准，若更严取更短（`library-sync.md §5.4`）。

## 4. 失效与重新挂载【新】

- **失效判定**：扫描后比对，链上的 `source + external_id` 不在新清单里 ⇒ 链状态 `stale`（记 `missing_since`）。**不删链**。
  - **再次出现 ⇒ 自动恢复 `active`**（比如库临时离线又回来了，不该让人点两遍）。
- **UI**：该文档上显示「**来源已失效，请重新挂载**」+ 一个「重新挂载」动作。
- **重新挂载的两种方式**：
  1. **宿主建议**：用归一化标题在清单里找候选（纯确定性匹配，不问模型），列出"这条像不像原来那部"；
  2. **手动挑**：从清单里直接选一条。
- **重挂的语义**：新链 `active`，旧链标记 `replaced`（保留可追溯：这个文档曾经挂过哪个条目）。
- **文档不动**：正文、版本、关系、资料全部保留。**失效只影响链，不影响文档。**

## 5. 写正文【后半段 · 对齐 llm_wiki 的 ingest】

- **两步式**：先"分析"（这是什么、与哪些节点有关、与现有内容矛不矛盾、建议怎么建）→ 再"写"。
- 分章骨架（含参考资料章）+ 每章长度/引用要求（技能文件承载，不写死在代码）。
- **长文分波写入** + 流式草稿（草稿落库，崩溃可恢复）+ 断点续写。
- **草稿 → 定稿 → 快照 → 回滚/diff**；定稿触发反哺（§3）。
- **多来源汇总 + 矛盾显式标注**（同作品的动画/漫画/游戏、外部资料互相打架）——llm_wiki 的看家本领。
- **封面/截图理解**（视觉模型读图 → 年份、版本：剧场版/OVA/重制）→ 先设计接口，实现可后置（花钱）。
- 系列主文 / 合集（节点是 series/universe 时走这条路）。

## 6. 体检（Lint）【我们缺，必须先补】

- **确定性检查**：孤立节点（无关系边）· 缺正文（状态与内容漂移）· 重复标题/别名 · 未挂链的库条目 · **失效链未重挂** · **定稿未反哺 / 反哺失败** · 长期未定稿的草稿 · 库里条目元数据变更未同步。
- **结构洞察**：松散社区、桥节点、孤立页（4 信号相关性 + 社区发现）。
- **深度研究**：缺口 → 生成搜索题 → 联网 → 汇总回库（直接喂"参考资料"章）→ 先设计接口，可后置。
- **级联清理**：删源/解链时，谁该归档、谁只该摘掉一条链（文档不因链消失而被删）。

## 6.5 关系网与综合页（补 llm_wiki 的「网」）

> 详见 `v2-from-v1.md §3.1`。这一层是 v1 缺、llm_wiki 有、v2 必须补的一等公民。

- **关系不只是展示**：`relations`（类型化有向边）要能被工具操作（`upsert_relation` / `detach_relation`）、被体检发现缺口、被综合页引用。
- **综合页** = `kind='doc'` 的**跨作品**页：角色 / 世界观 / 时间线 / 主题 / 创作者。它们引用多个 `work` 节点，是 llm_wiki "synthesis" 的对位物。
- **导航由宿主确定性维护**：首页概览 / 索引页 / 系列页的目录骨架由代码更新（新增节点就追加一行），**模型只写正文、不重写整篇导航**。
- **判据**：任何"把多个作品连起来看"的产出 → 综合页；任何"单部作品内部"的产出 → 它的 `work` 文档。

## 7. 问答与产出

- 只依据库内容回答 + 引用到节点（可点回原文）。
- **答案可回写**：好回答存成"资料"或正文小节（llm_wiki 的"探索复利"）。
- 跨作品对比 / 清单类产出。

## 8. 检索

- 全文检索 + 别名归一（**方案已冻结**：归一化精确匹配 + `pg_trgm` 模糊/trigram；应用侧 **bigram** 兜底——`zhparser`/`pg_jieba`/`pg_bigm` 不上）。
- 语义检索（pgvector）+ 相似作品发现 → 表结构预留，功能后置。

## 9. 对外与运维

- MCP server / 本地 API（把库交给别的 agent 读）——先做 server，client 后议。
- 技能体系（SKILL.md，可切换/可分享）。
- 库导出/导入 + PG 备份。
- 设置（模型 / 思考档 / 三源地址与密钥 / 扫描周期）；用量与成本可见。
- 三面板布局（飞书蓝本）：左树 / 中文档 / 右 AI 助手。

## 10. 明确不做

多租户、权限组、发布工作流、IM 机器人（钉钉/企微/微信）、桌面端打包、Obsidian vault 兼容、移动端、多语言界面。
