# WikiAtlas v2 · AI 设计

> 技能体系见 `docs/skills.md`；工具与进程见 `docs/backend.md`；数据落地见 `docs/database.md`。
> **工具面契约**见 `tools.md`；**提示词与质量门**见 `prompts.md`；**行为知识（写 agent 前必读）**见 `behavior-notes.md`；决策冻结见 `README.md §3`。

## 0. 定位

**AI 是这个库的写作者**（不是聊天窗口）。所以"AI 设计"= 它能写什么 · 在哪儿写 · 写到什么程度 · 写完落到哪。

llm_wiki 的骨架照搬：**Ingest（进料）/ Query（问答）/ Lint（体检）** 三操作；关键差异是我们的原料是**外部媒体库的清单**，不是一次性丢进来的文档。

## 1. 能力面

| # | 能力 | 优先级 |
|---|---|---|
| 1 | **写正文**（从节点产出分章正文） | v1 必须有 |
| 2 | **分析**（两步式的第一步：这是什么/与谁有关/矛盾缺口/建议怎么建） | v1 必须有 |
| 3 | **修订**（定点改章节、按意见改） | v1 必须有 |
| 4 | **问答**（只据库内容 + 引用到节点） | v1 必须有 |
| 5 | **结构操作**（建关系、解链、重挂、归档，受护栏） | v1 必须有 |
| 6 | **体检辅助**（把确定性发现转成"要不要修、怎么修"的建议） | v1 必须有 |
| 7 | **看图**（封面/截图 → 年份、版本、素材描述） | 后置（**默认关**） |
| 8 | **研究**（联网补资料 → 喂"参考资料"章） | 后置（**默认关**） |

## 2. 工单（run）

**目标类型**：
- 节点（写正文 / 修订 / 问答）
- 资料（问答 / 修订）
- **全局**（体检建议、研究——不挂具体节点）
- ❌ **未建档的库条目**：只能做「分析」，**不能写正文**（先建档）

**上下文装配**（顺序即优先级）：

```
① 技能目录（L0，常驻，短）         ← 见 docs/skills.md
② 索引面（宿主生成，零 LLM）：这个库有什么
③ 目标现状：节点、层级、别名、正文大纲、关系、资料
④ 媒体链与反哺状态（新）：已挂链哪个条目、定稿是否已反哺、链是否失效
⑤ 按需读的技能正文（模型自己 read_skill）
预算分配（借 llm_wiki 的可配置窗口）：系统 15% · 索引 10% · 目标 40% · 历史 20% · 余量 15%
裁剪顺序：关系 → 资料 → 兄弟 → 子节点 → 最后只留"祖先路径 + 目标本身"
```

**窗口大小可配置**（4K–1M 滑块）——不同模型能力差得远，写死在代码里是错的。

**产出落点三档（固定）**：

| 落点 | 谁定 | 例子 |
|---|---|---|
| **草稿正文** | 模型写，**永远不能定稿** | 写正文 / 修订 |
| **结构操作** | 直接做（受写者矩阵与护栏） | 建关系、解链、重挂 |
| **建议** | 进 Review 队列，人裁决 | 建档、关联、合并、忽略 |

**生命周期**：入队 → 执行（LLM 在事务外）→ **草稿落库**（节流写，崩溃可恢复）→ 质量门（代码）→ 定稿（人点，或宿主按质量门自动）→ **反哺**（定稿触发）。

**会话**：append-only 的 `session_messages` + 可重放（v1 结构直接重用）；**断点续跑**是队列 + 租约带来的（不再是"重启全标 interrupted"）。

## 3. 七个决定（已拍板）

| # | 问题 | 决定 |
|---|---|---|
| 1 | 建档与写正文绑不绑 | **不绑**。建档零成本（点一下），写正文花钱（要额度）——分开才不会被批量点击烧掉。但界面在"建档"后给人一眼可点的下一步 |
| 2 | AI 能不能替人建档 | **不能**。建档/挂链是核心动作、是人的决定；模型只能**建议建档**。但模型**能直接建关系**（解链/重挂也归模型，但受护栏） |
| 3 | 未建档条目能不能直接写正文 | **不能**，先建档。但「分析」可以对未建档条目做，产出建议 |
| 4 | 两步式第一步给谁看 | **内部为主**（喂第二步）；但涉及**建档/合并/归档**的结论进 Review 队列 |
| 5 | 问答产物回写吗 | 能存成「**资料**」，**不直接改正文**——正文改动一律走修订（才有版本可追溯） |
| 6 | 模型路由 | **可分别配**：写正文 / 分析 / 看图 / 研究。默认全部走设置里的主模型；**分析步默认用更便宜的档**（v1 的 effort 参数） |
| 7 | 哪些花钱项默认关 | **看图、研究默认关**，用户开了才跑 |

## 4. 两步式（进料分析 → 生成）

**第一步 · 分析**（便宜档，产出 JSON）：
- 这条是什么（作品 / 版本 / 载体判定）
- 与库里哪些节点有关（候选 + 依据）
- 与现有内容**矛不矛盾**（同段故事被别的作品讲过？）
- 建议：该建在哪、该不该合并、要不要研究

**第二步 · 生成**（主模型）：骨架 → 分章（**波次**写入）→ 收尾（题记、参考资料）。

**何时跳过第一步**：只有"补一章/改一段"这类小任务跳过；整篇必走。

## 5. 技能

见 `docs/skills.md`。要点：**L0 目录常驻、正文按需 `read_skill`**；机械规则进质量门（代码），技能只留判断；技能可声明需要的**结构化用户输入**（表单）。

## 6. 工具面

- **读工具 / 写工具 / 控制工具**三类；只有**用户显式选择**（`docMode=read`、`oneShot`）才剥写工具——**意图不决定能力面**。
- 运行时二次校验：被剥掉的写工具即使被幻觉调用也拒绝执行。
- 批量工具：**波次 + 预检在前 + 全成或全不成 + 上限**。
- 新增（v1 缺，靠 API）：`detach_link`（解链）、`relink`（重挂）、`list_skills` / `read_skill`。
- 工具 schema 由类型生成（Rust `schemars`），一致性由测试守。

## 7. 提示词分层

沿用 v1 调出来的分段（顺序也是它定的）：身份 → 意图 → 工具面 → 会话记忆 → 探查 → 研究 → 上下文窗口 → 文档模式 → **技能** → 收尾 → 语言。

v2 改一处：**技能段只渲染 L0 目录**（不再把正文塞进来）。

## 8. 质量门（代码，与技能分工）

**机械项一律由代码查**（不写在提示词里）：

- 一级章齐全、编号连续无空号；无 `## 引言`
- 章名按介质映射正确
- 字段行格式（`- 名：值`、值里无判断句）
- `:::epigraph` **有且仅有一个**；引用式有署名行
- 参考资料条数下限；**每条引用指向存在的节点**（v1 查不了这个）
- 缺口只能是 `待核实` 或整行删除（禁"据说/广受好评"之类）
- 全篇字数下限
- **新增**：正文里若提到"来源/版本"，与链和反哺状态一致（失效链要在正文交代）

**不过质量门怎么办**：留草稿 + 把问题回给模型**一次**纠错机会；仍不过 → 留草稿待人工（v1 是"标 draft + 提醒"，保留这个语义）。

## 9. Review 队列（异步裁决）

- **动作枚举**（防幻觉，借 llm_wiki）：`建档` / `关联` / `合并` / `研究` / `忽略`。
- 每条建议带：**为什么**（模型依据）+ **怎么做**（点下去会发生什么）+ 预生成的搜索词（如果是研究）。
- 不阻塞任何工单；人随时处理。

## 10. 护栏（v1 验证过的，全保留）

空写拒绝 · 截断守卫（`>200 → <50` 拒绝）· 归档节点拒写 · 参数 JSON 错就报错别猜 · 重复调用分级 · 联网预算 · **截断必须说话** · 破坏性写只许自有且可回滚的对象。

## 11. 成本与可见性

- 每次工单的 token / 成本可见；批量上限；**看图与研究默认关**。
- 定稿触发反哺是幂等的（同 `synced_ver` 不重推），避免重复成本。

## 12. 验收（怎么算"AI 做对了"）

| 手段 | 内容 |
|---|---|
| **样例回归** | **v1 的 6 篇成品 = 用户认可"写得好"的定义**；改技能/提示词后必须跑，看是否回退 |
| 质量门 | 机械项逐条（§8） |
| 真跑 | 副本库上跑完整主链：分析 → 建档 → 写 → 定稿 → 反哺 → 失效重挂 |
| 触发纪律 | 记录 `read_skill` 调用，离线评估"该读的读了没、不该读的没读" |
| 成本纪律 | 触发真模型调用的测试要显式确认（历史上误花过一次额度） |

## 13. 已拍板（原"待定"，见 `README.md §3`）

1. **默认档位分配**：写正文 / 问答走设置里的主模型（默认档）；**分析步走更便宜的档（默认 `low`，可配）**；看图 / 研究默认关。思考档合法值只有 `none/minimal/low/medium/high/xhigh/max`（**没有 `off`**）——机械判定用 `none`。
2. **Komga 摘要**：见 `library-sync.md §5.4`（首段、去 markdown、≤500 字、超 `…`）。
3. **质量门"引用指向存在的节点"**：**保持**——但只校验**内部节点引用**（`[[节点]]` / 工具产出的节点 id）；**外部链接（URL）不算**，不进这条检查。判定边界见 `prompts.md §3`。
