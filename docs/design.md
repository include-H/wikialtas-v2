## 0. 给产品方的一页纸（不用懂技术）

**Atlas 是什么**：你的游戏 / 影视 / 书库旁边的一座"资料馆"。库里每一部作品，都可以有一篇像样的百科文章；文章由 AI 馆员 Atlas 去网上查资料、整理、写好，你过目后点「定稿」，它会自动把简介推回你的媒体库。

**你会怎么用它**：

```
打开 → 首页：看到「最近更新」和「还有多少部作品没文章」
     → 媒体库池子：挑一部没文章的作品，点「建档」（不花钱，一秒）
     → 文章页：点「让 Atlas 写」
         ① Atlas 先去查资料，右边能看到它查了哪些网站、记下了哪些事实（"事实账本"）
         ② 然后按章写，正文一段一段出现在页面上
         ③ 写完自动体检（章节齐不齐、有没有空话），不过就自己改一遍
     → 你读一遍，改两句，点「定稿」→ 简介自动推回 GameAtlas / Komga
```

**这次改了什么，一句话**：以前 Atlas 是"一边查一边写"，结果查着查着就忘了写；现在改成**先查完、记成账本，再照着账本写**——查和写分开，各管各的，而且账本留档，以后改文章、问问题都能直接用。

## 1. 诊断：为什么要改

| # | 现象 | 根因 | 改法（见后文） |
|---|---|---|---|
| 1 | M4 实测两次：12 轮里全在检索、一字没写 | 研究和写作塞在同一个循环里，轮次预算被研究吃光；"最多 4 次检索"的提示约束不住 | **三段式管线**（§2）：写的阶段**手里没有检索工具**，从结构上不可能"只查不写" |
| 2 | 质量目标（`/root/Game_Wiki`）达不到 | 那 36 篇是强模型 + 成熟 harness + 不限轮次 + 能读全文网页产出的；内置 loop 只有摘要片段、12 轮 | 研究段加 `web_fetch`、按**覆盖率**而不是次数收工（§2.2）；验收分档（§4） |
| 3 | 检索结果写完就丢 | 没有"原始资料层"——llm_wiki 模式的核心恰恰是"资料不可变、wiki 可再编译" | **事实账本落库**成资料（§2.3），修订/问答/体检都复用 |
| 4 | 核心价值最晚兑现 | 反哺（核心链第 ⑤ 步）排在 M7，关系网/体检这些锦上添花排在它前面 | **路线图重排**（§5） |
| 5 | 界面"能用但没打扮" | M0–M3 只顾打通链路 | **前端视觉收口**（§6，本轮已落地） |

## 2. 写作管线：研究 → 骨架 → 生成

### 2.1 总览

```
           ┌──────────── 研究 research ────────────┐  ┌─ 骨架 outline ─┐  ┌──────── 生成 generation ────────┐
输入       节点 + 媒体链 + 已有账本(如有)               账本               账本 + 骨架 + 技能
工具       web_search · web_fetch · ledger_put ·       （无工具，        patch_section（按章波次）·
           read_skill · read_node                      结构化输出）      read_skill · read_ledger
           ✗ 不能写正文                                                  ✗ 不能检索
产出       「事实账本」资料（落库，可人工编辑）         骨架 JSON         草稿正文（流式进页面）
收工条件   必填字段覆盖率达标 or 预算用尽              一次产出          所有章写完
质量门     账本门（§3.1）                              骨架门            正文门（`prompts.md §3`）+ 引用门
模型档     可配（默认主模型，effort=low）              主模型            主模型
```

- **三段是同一个工单（run）里的三个阶段（`run.phase`）**，不是三个工单。用户看到的是一件事："让 Atlas 写"。阶段切换发 `wikiatlas.phase` 事件，右栏时间线按阶段分组。
- **小任务跳过前两段**：「改第 4 章」「补一句」这类修订，直接进生成段，账本作为只读上下文。
- **已有账本就不重查**：账本存在且未过期（默认 90 天），研究段只补缺口（未覆盖字段 + `待核实` 行）。

### 2.2 研究段：怎么算"查够了"

**按覆盖率收工，不按次数。** 每种介质有一张必填字段清单（取自 `media-*` 技能的字段表），研究段的目标就是把清单填满：

| 介质 | 必填（缺一个都不收工，除非预算用尽） |
|---|---|
| 游戏 | 原名 · 开发 · 发行 · 首发日期 · 首发平台 · 版本关系 · 世界观 · 剧情（含结局） · 核心玩法机制 ≥3 · 主要角色 ≥4 · 评价（评分或销量或奖项 ≥1） · 题记素材 |
| 影视 | 原名 · 导演 · 编剧 · 主演 · 首映/首播 · 集数或片长 · 剧情（含结局） · 主要角色 ≥4 · 评价 ≥1 · 题记素材 |
| 图书/漫画 | 原名 · 作者 · 出版社/连载志 · 起止时间 · 卷数 · 剧情（含结局） · 主要角色 ≥4 · 评价 ≥1 · 题记素材 |

- 每轮工具结果后，宿主**用代码**算覆盖率，把"还缺：首发平台、评价"作为下一轮的提示注入——模型不需要自己记账。
- **预算**（D72 更新）：默认检索 ≤ 24 次、抓取 ≤ 16 页、轮次 ≤ 48（设置页可配）。预算用尽仍未覆盖 → 缺的字段在账本里记 `待核实`，照样进下一段（**宁可带缺口写完，不许卡死**）。搜索本身是 Exa/Brave/DeepSeek 聚合，一次调用会先拉大候选池再 RRF 融合，因此不应再为了“多拿几条”连续空转。
- `web_fetch` 返回正文抽取后的纯文本，**超 12k 字截断并明说截断**（护栏"截断必须说话"）。
- ⚠️ 媒体库年份常是再发行年——账本里"首发日期"的来源不能是媒体库本身。

### 2.3 事实账本（新的一等公民）

**存在哪**：作品节点下的一个资料节点（`kind='doc'`、`tags=['账本']`、标题「事实账本」）。不加新表——它就是一篇 Markdown，人能在同一个编辑器里看、改。

**长什么样**（固定格式，代码解析）：

```markdown
## 断言
| # | 字段 | 断言 | 来源 | 状态 |
|---|---|---|---|---|
| 1 | 首发日期 | 2006-03-09，Windows | S1,S3 | 已核实 |
| 2 | 港台译名 | — | — | 待核实 |
| 3 | 销量 | 日本首周 4.2 万 / 全球 30 万 | S2,S4 | 冲突 |

## 来源
- [S1] 日本 Falcom 官方商品页 — https://… — 抓取 2026-10-12 — 「……原文摘录（≤300 字）……」
- [S2] …
```

- 状态只有三种：`已核实`（≥1 个权威来源，且无冲突）· `冲突`（来源说法不一，**正文里要写出分歧**）· `待核实`（查不到，正文写「待核实」三个字）。
- 写工具 `ledger_put` 只追加/改行，不整篇重写（护栏：同"大 wiki 不整篇重写"）。
- **复用**：修订时作只读上下文；问答（M8）首选引用账本；体检（M6）把 `待核实` 行列成"可补缺口"。

### 2.4 骨架段

一次结构化输出：`{ title, note, epigraph: {kind, source_id}, chapters: [{no, name, sections: [{name, ledger_rows: [#…]}]}] }`。
- **骨架门（代码）**：章名按介质映射正确、编号连续、每节至少挂 1 条账本行（"没有事实支撑的小节不许出现"）。
- 骨架同时决定第 8 章（名台词）留不留：账本里没有可指出处的名句 → 直接不出这章。

### 2.5 生成段

- **按章写**：每章一次 `patch_section` 调用，按骨架顺序波次落草稿。好处：单次失败只损失一章；流式体验是"一章一章长出来"；质量门可以逐章先查。
- 文档头（标题、说明、题记）作为第 0 章先写。
- **引用门（新增，代码）**：「参考资料」章的每一条必须对应账本里的某个 `[Sn]`；正文里的具体数字/日期，抽样比对账本（不在账本里的数字记为提醒，不硬拦）。
- 写完跑正文门（`prompts.md §3`），不过 → 回给模型一次，只重写不过的章（不再整篇重写）。

### 2.6 执行引擎

- **默认用内置 Rust 循环**（M3 已打通，流式投影是体验核心，值得自己做）。
- 研究段抽象成 `ResearchRunner` 接口，**预留外部 harness 实现**（通过 MCP 暴露 `ledger_put` / `read_node`）。何时切换由数据决定：§4 的 A/B 评测里，若内置研究段的账本覆盖率持续 < 80%，就把研究段交给外部 harness，生成段仍内置。

## 4. 验收分档（替换 M4 原来的"达到 Game_Wiki 档"一刀切）

| 档 | 判据 | 作用 |
|---|---|---|
| **规则档** | 过正文门 + 骨架门 + 引用门；账本覆盖率 ≥ 80% | **M4 的验收线**（阻塞里程碑） |
| **产出档** | 与 `/root/Game_Wiki` 同名条目对照：字数 ≥ 70%、`待核实` 数 ≤ 1.5 倍、章节结构一致；人工盲评不劣于 | **持续评测指标**（不阻塞里程碑，每次改提示词/技能跑一次） |

**A/B 基准集**：Game_Wiki 已有的条目（仙剑 1/2/3、生化危机系列、使命召唤系列）。同一条目分别跑内置管线，产出与 Game_Wiki 对照，结论写进 `eval-cases.md`。⚠️ 真模型调用花钱，跑之前确认。

## 5. 路线图重排

核心链是"建档 → 写 → 定稿 → **反哺**"，反哺不到位，这个应用对媒体库就没有产生价值。所以：

| 顺序 | 里程碑 | 变化 |
|---|---|---|
| 1 | **M4 写作与质量门** | 按本文 §2–§4 重新定义：三段式 + 账本 + 规则档验收 |
| 2 | **M7 反哺与失效重挂** | **提前**（原排第 7） |
| 3 | M5 关系与综合 | 顺延 |
| 4 | M6 Review 与体检 | 顺延；体检直接复用账本的 `待核实` 行 |
| 5 | M8 检索与问答 | 顺延；问答首选引用账本 |
| 6 | M9 对外与运维 | 顺延；MCP 的只读面若 §2.6 需要外部 harness 则提前做 |

里程碑编号不变（文档里到处引用），只改执行顺序。

## 6. 前端视觉方案（本轮已落地）

> 视觉语言不变：**飞书文档的布局语法 + AntD token + 紫色只给 AI**（`frontend.md §2.0 §6`）。这里定的是"打扮完"长什么样。

### 6.1 首页（打开产品的第一屏）

```
┌───────────────── 居中 880px ─────────────────┐
│ 早上好 · 你的文档库                              │
│ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐ │
│ │ 作品  12│ │ 已定稿 5│ │ 草稿中 7│ │未建档 1.7k│ ← 统计卡（未建档→点进池子）
│ └────────┘ └────────┘ └────────┘ └────────┘ │
│ 最近更新                                       │
│  ▣ 空之轨迹 SC   游戏 · 轨迹系列      定稿 v3 · 2 小时前 │
│  ▣ 风之谷（漫画） 漫画               草稿 · 昨天         │
│  …（12 条，点击进正文）                           │
└──────────────────────────────────────────────┘
```
- 没选节点时主区就是首页；左栏「主页」高亮。空库时给"去媒体库池子建档"的引导。

### 6.2 左栏
- 导航项带图标：主页 / 媒体库池子（带未建档计数徽标）。
- **树节点图标按种类**：宇宙 🌐、系列 📁、作品按介质（游戏 🎮 影视 🎬 剧集 📺 漫画/图书 📖）、资料 📄；账本资料用专门图标。
- **状态点**：草稿 = 橙点、定稿 = 无点（干净）、归档 = 灰字。

### 6.3 文档页
- **一条阅读栏**：标题、meta 行、说明、题记、正文**同一个 760px 居中栏**（之前标题居中、正文通栏，左右不齐）。
- meta 行：`游戏 · 作品` 中文标签 ｜ `定稿 v3` / `草稿` 状态 ｜ `已保存 · 10:21`（脏了显示「保存中…」）｜ 右侧：阅读/编辑切换 · **紫色「让 Atlas 写」** · 「定稿」 · **「⋯」**。
- **「⋯」菜单**：版本历史（抽屉：版本列表 + 预览 + 「恢复为草稿」）· 节点信息 · 复制 Markdown · 归档（灰，M6 前不可用并说明原因）。
- **来源条**（作品节点、有链时）：`🔗 GameAtlas《英雄传说 空之轨迹 SC》· 正片` 一行；链失效变黄条「来源已失效，请重新挂载」。
- **实时写入**：Atlas 写这篇时，正文区切成**只读实时视图**，顶部紫色细条「Atlas 正在写入 · 第 4 章」，最后一段挂 `live-tail`（压暗 + 文末紫色脉动光标），写完的段落渐显；收工后切回编辑器并载入服务端草稿。
- 正文排版：列表项紧凑（项间距 2px 而不是段距）、表格斑马纹 + 表头底色、`---` 分隔线弱化、`##` 章标题下加细线（飞书文档的章节感）。

### 6.4 Atlas 右栏（时间线）
- 头部：紫色标识 + 「Atlas」+ 当前节点 chip + 运行状态。
- **空态**：一句问候 + 三个起手式按钮（「写这篇的 Wiki」「补全待核实」「检查这篇有什么问题」），点了填进输入框。
- **工作态 = 顺流时间线**（v1 VISUAL_SPEC §4）：
  - 用户消息：右对齐浅灰气泡；
  - 阶段标题：`研究` / `骨架` / `生成`，带阶段图标与用时；
  - 工具行折叠条：「已检索 6 次 · 读取 2 份技能」，展开看逐条（图标 + 人话摘要，不摊 JSON）；
  - 叙事：模型说的话，普通文字；
  - 写入卡：「正在写入正文 · 3,214 字」+ 紫色进度脉动，点击滚到正文；
  - 质量门卡：通过 = 绿勾一行；不过 = 列出问题条目；
  - 收尾：「完成 · 用时 2m14s · 草稿已保存，去定稿 →」。
- 输入框：AntD X `Sender`，Enter 发送。

### 6.5 池子
- 行 = 封面 + 标题 + 年份 + 来源徽标 + 容器；右侧主操作「建档」直显，其余收进「⋯」。（M1 已基本到位，本轮只统一视觉。）

### 6.6 视觉验收
- `scripts/layout-check.sh` 原 32 项不回退；新增截图 `_baseline/visual-*.png`（首页 / 文档 / 实时写入 / 版本抽屉 / Atlas 时间线）。
