# WikiAtlas v2 · 前端设计

> 前置于功能清单：见 `docs/features.md`。**布局蓝本 = 飞书云文档三面板**（这是布局，不是视觉母本；视觉母本随 Ant Design 走）。
> 接口与事件契约见 `docs/api.md`；验收见 `docs/testing.md`；v1→v2 前端取舍见 `docs/v2-from-v1.md §2.6`。

## 1. 基座选型

| 层 | 选 | 理由 |
|---|---|---|
| 框架 | React 19 + Vite + TypeScript（strict） | 与 v1 同源，团队已熟 |
| 设计系统 | **Ant Design v6**（实测装到 6.6） | 基座；token 化，主题可整体替换。⚠️ 原计划写的是 v5，实际 npm 最新已是 v6——API 基本兼容，已按 v6 落地 |
| AI 组件 | **@ant-design/x** + `XProvider` | Bubble / Sender / Conversations / ThoughtChain / Sources / Mermaid / CodeHighlighter 等，正是右面板要的 |
| 服务端状态 | **TanStack Query** | v1 是手写 `fetch + useState` + 8 处手动 `refreshTree()`，导致同一份真相散落；v2 统一交给它（缓存、失效、重试、stale 策略） |
| 客户端状态 | **Zustand**（极小） | 只放"面板开合 / 当前选中 / 草稿订阅游标 / 主题"这类**不是服务端数据**的东西 |
| 编辑器 | **Milkdown**（已定，实测 7.22） | 存储格式就是 Markdown，**文档模型与 `body_md` 之间没有转换层**——这是选它而不是 Tiptap 的原因（Tiptap 内部是 ProseMirror JSON，往返要盯格式丢失）。**不引它的主题包**（nord 之类自带配色会绕开 token），外观用 AntD CSS 变量自己写。v1 的 BlockNote 则会把 Mantine 拖成第三套设计系统，直接排除 |
| 路由 | react-router v7 | 沿用 v1 心智 |

**编辑器必须自带这三样**（缺一个就会表现成「编辑器有问题」）：`listener`（把 markdown 同步给宿主）· **`clipboard`**（没有它时 ProseMirror 只按纯文本插入，粘进来的 markdown——标题/表格/列表/加粗——全成字面量，这正是「粘贴文档不渲染」的根因）· **`history`**（预设不含它，缺了 Ctrl+Z 直接无效）。粘贴整篇文档时，文档头（`# 标题` / `> 说明` / `:::epigraph`）先经编辑器的 `transformPastedText` 交给文档面板摘走，与**装载**时的 `splitDoc` 走同一条路（只在空正文里这么做，免得粘进正文中间时把普通 `#` 抢成文档头）。

**真相只有一份，且不在前端**：所有可变状态（树、节点、正文、链、草稿、工单、体检结果）都是服务端数据 → Query 管；前端不自己攒草稿（见 §5）。


### 2.0 视觉骨架：照 v1（已落地）

用户 2026-10 的要求：**「按照旧版本的前端，把现在的前端改成他的样子」**。所以视觉语言回到 v1——它的成文规格在 `archive/v1/VISUAL_SPEC.md`（**母本 = 飞书文档**：留着宽度、细边框、蓝色选中/主按钮、**紫色只给 AI**），我们只是把它**实现到 AntD 上**（组件基座仍是 AntD，视觉语言来自 v1）。

> ⚠️ **v1 的准绳是它的代码，不是它那份 VISUAL_SPEC 的早年文字。** 以 `archive/v1/frontend/src/components/shell/AppShell.tsx` 为准：`Layout.Sider`（左栏 **全高**，280px / 收起 48px）在左，`TopBar` 在 `Layout.Content` 里（**只在内容区上方，不在左栏上方**），`RightSidebar` 在内容区右侧。
> 因此 **`VISUAL_SPEC.md §1.1` 里"顶部导航栏左上 = Logo"那句是过期描述**：实际实现把**品牌/搜索/导航放进左栏**（`SideNav`），顶栏只留（面包屑 + 最近更新 + 主题/可见性等动作）。**本文 §2 已按代码对齐**，冲突时以本节 + 代码为准。
> **一句话**：**「怎么展示」照 v1（布局骨架 + 视觉语言 + 交互），「怎么写」全换（Semi→AntD、BlockNote→Milkdown、手写状态→TanStack Query、全局 CSS→token+CSS Modules）。**

| 区域 | 规格（= v1） |
|---|---|
| 左栏 | **280px**，白底 + 一条细右边线；内部：品牌 → 搜索框 → 全局导航 → 「我的文档库」+ 新建 → 树 → 底部「N 个节点」 |
| 顶栏 | **52px**，只在**内容区**上方（左栏是全高的）；左 = 面包屑（根「我的文档库」+ 当前路径）+ 小字「最近修改：x 前」；右 = 布局开关 · **紫色「✦ 问 Altas」** |
| 文档区 | **大纲栏 185px**（从 `##` / `###` 解析、点击跳转、滚动跟随）+ 居中书页列（标题 32px、meta 行「状态 · vN」+ 定稿按钮） |
| **题记** | **书页留白**（VISUAL_SPEC §3）：上下细分隔线、一对对角装饰引号（CSS 伪元素）、**原文小字 / 中文译文大字**的逐行交替、署名右对齐，**无底色无边框**——不是卡片、也不是普通 blockquote。排版模型直接移植 v1 的 `lib/epigraph.ts`（判据是「这一行是不是中文」，不是「是不是拉丁」；日文行夹汉字，得先靠假名认成日文才降为小字） |
| 右栏 | **Altas 480px**，**默认收起**（v1 的规矩；默认打开会把 1280 宽的正文挤到 300 多像素）；紫色只出现在这一栏与「问 Altas」 |

**题记的落地方式（值得记一笔）**：源码（`:::epigraph` 围栏）**不进正文编辑器**——文档面板在装载时用 `splitBody` 把围栏摘出来、交给 `<Epigraph>` 渲染，保存时用 `joinBody` 接回去。v1 也是这个做法（编辑态按渲染形态显示，点开才编辑源码）。清单上有断言守这条**往返**：改题记 → 草稿 → 定稿，围栏在草稿/定稿/快照三处都必须在。

**明确还没搬的（别当成漏做）**：「关联与媒体」标签（等链落地）、顶栏「⋯」菜单与作者行、面板开合状态记 localStorage、媒体库建议页（左栏里**明确禁用**，不做假入口）、题记的就地编辑（现在是悬停出现 ✎、开小弹层改围栏原文）。

### 2.1 断点行为（已落地；`scripts/layout-check.sh` 32 项验收）

| 视口 | 布局 |
|---|---|
| **≥ 992** | 三栏。左右宽度用 antd **`Splitter`**（左 240–400 / 右 360–520，**可拖可收**），顶栏另有两个开关按钮；中间自适应 |
| **768–992** | 三栏，但**右栏默认收起**——不收的话中间只剩一百多像素，正文没法看 |
| **< 768** | **单栏**（只有正文）+ 左右各一个 `Drawer`，顶栏给「知识库」「AI」两个入口；在抽屉里选完节点**自动收起**，把地方让给正文 |

- **高度：面板一律触底**——`.shell` 撑满视口，滚动交给各面板自己（`.pane` / `.doc-body`），**页面本身不出纵向滚动条**；正文再长也只滚正文区。
  ⚠️ **必须记住的坑**：antd 的 `<App>` 会多包一层 `div.ant-app`（高度 auto），`height: 100%` 的链会**断在它那儿**——表现就是「面板按内容高度算、不触底」。修法是给 `<App>` 传自己的 `className`（`app-root`）把它撑住，**不要去覆盖 `.ant-app`**。
- **点已选中的节点是「反选」**：antd Tree 这时给 `onSelect` 一个**空数组** → 空选必须**保持当前节点**，否则文档面板会莫名其妙变空。
- 顶栏 = 品牌 + **面包屑**（从树往上走；窄屏时树被收起来了，靠它知道自己在哪）+ 布局开关。
- 断点一变就回到该断点的**默认宽度**（手动拖过的宽度不跨断点保留，免得中屏挤出个 150px 的正文）。
- ⚠️ **已知没验到的**：拖拽**手势**本身。CDP 合成的鼠标事件推不动 antd Splitter 的提交路径（它挂在 React `onMouseDown` 上、读 `pageX`、并在 effect 里往 `window` 挂 `mousemove` —— 派发 PointerEvent 也不行）。脚本改验「**antd 自带的收起/展开 → 我们的状态同步**」——那是**同一段提交代码**（`onResizeEnd(sizes) → setLeft/setRight`），映射对了；真手势留给 Playwright 级别的真实输入。

- **① 左**：知识库树（多面板切换：树 / 搜索 / **池子**（未挂链的库条目）/ 体检）。池子与体检是本应用的"进料口"和"维护口"，值得各占一个左栏面板。
- **② 中**：文档。含 **来源状态条**——正常时显示"已挂链：Emby《X》(2024)"；失效时显示**「来源已失效，请重新挂载」**+ 动作按钮；反哺状态（已推 v12 / 待推 / 失败+原因+重推）。
- **③ 右**：AI 助手。上半对话（AntD X），下半宿主部件（任务面板 / 用量环 / 提醒条 / 草稿进度）——**这条纪律沿用 v1**：整条 `response.*` 交给 X 的 runtime，宿主事件走自己的部件，不混。

## 3. AntD X 组件的落位

| X 组件 | 我们用在哪 |
|---|---|
| `Bubble` | 对话气泡（含 reasoning / tool 的自定义气泡体） |
| `Conversations` | 右侧会话列表（一个文档 = 一个默认会话，可另开） |
| `Sender` | 输入框（含 `@` 提及节点、模式切换：问答 / 写正文 / 修订） |
| `Actions` | 每条回答的操作条：复制 / 引用到正文 / 存为资料 / 重跑 |
| `Sources` | **引用来源**：回答/正文里的引用节点，点击跳转（我们的引用天然是节点） |
| `Attachments` | 素材（海报/截图/文本）挂进会话 |
| `Suggestion` | 下一步建议（"这条要不要顺手把漫画版也建了"） |
| `Prompts` / `Welcome` | 空态引导（"告诉我你想补哪部作品"） |
| `Think` / `ThoughtChain` | 模型的思考与工具链（我们的 run 事件里有 reasoning / function_call） |
| `Mermaid` | 正文与回答里的关系图（**v1 缺这个能力**） |
| `CodeHighlighter` | 代码块 |

**我们自己要补的**（X 不管或不够）：任务面板（todo）、用量环（token/成本）、提醒条（notice）、草稿进度、树、池子、体检面板、来源/反哺状态条。

## 4. 事件契约与适配层（这一层是重写的关键）

后端出两条事件线（沿用 v1 的设计，它是对的）：

- **`response.*`**：OpenAI Responses API 形状（`output_item.added/done`、`output_text.delta`、`reasoning_summary_text.delta`、`function_call_arguments.delta`…）→ **交给 AntD X 的 runtime**。
- **`wikiatlas.*`**：宿主事件（`todo` / `usage` / `notice` / `content.staging` / `content.delta` / `content.committed` / `tree` / `run.end` / **`link.*`** / **`sync.*`**（新增：链与反哺））→ **宿主部件消费**。

规矩：

1. **适配层单独成模块**（`src/ai/transport/`）：把 `response.*` 翻译成 X 的会话模型。**这是换任何 UI 框架时唯一要重写的地方**，v1 它是隐式写在 `reduceRun.ts` 里的。
2. **类型由后端生成**：从 Rust 的事件常量生成 TS 联合类型（`ts-rs` / `typeshare`）——v1 把事件清单写在**三处**（`types.ts` + 两个数组），必然漂移。
3. **SSE 纪律**（v1 是对的，保留）：游标只在**成功处理**后推进；seq 缺口/解析失败 → 重新基线；断线指数退避。
4. **草稿只读**：流式 `content.delta` 仅是加速通道，重连后一律从**服务端的草稿**重新基线。

## 5. 草稿与定稿的客户端模型

| 状态 | 来源 | 前端行为 |
|---|---|---|
| 草稿（模型正在写） | **服务端的草稿行** | 只读展示；`content.delta` 增量加速；重连后重新拉草稿 |
| 定稿 | 服务端正文 `contents` | **人编辑的落库路线（已定）**：改动防抖 1.5s → 写 `content_drafts`（不产生快照）→ 点「定稿」才在一个事务里写 `contents` 版本 +1、`content_versions` 快照、`write_events`、清草稿。乐观并发不符 → 横幅给两个明确选择：「载入最新（丢弃我的）」/「以我的为准覆盖」。**人与模型共用同一条写路径**（AI 那面直接复用） |
| 反哺状态 | 服务端（每条链 × 每个目标） | 状态条显示；失败给原因 + 「重新推送」 |
| 链失效 | 服务端 | 横幅「来源已失效，请重新挂载」+ 重挂动作（可选：宿主建议的候选列表） |

**编辑器 × 存储的边界（实测的坑，两处各一份实现）**：Milkdown 之类的富文本编辑器会把**空段落**序列化成一行 `<br />`，直接存进 `body_md` 就是脏数据（会漏进 AI 的上下文与最终渲染）。规范化放在写路径入口：

- **Rust 侧是规范**（`domain::text::normalize_markdown`）：丢掉孤立的 `<br />` 行、连续空行折一个，任何写者（人 / 模型 / 宿主）都过这里；副作用是**正文有唯一规范形：总以换行结尾**。
- **前端必须同规则再来一份**（`src/markdown.ts`）：否则手里那份永远不等于「已保存的那份」，状态条会一直显示"有改动"。
- **改一处要改两处**——将来若做类型/规则生成，这是第一个该合并的地方。

### 5.5.3 为什么题记改法（不是偏离，是修坑）

v1 把 `:::epigraph` 做成**自定义块**，进出 BlockNote 的 markdown 往返是**有损的**（实测 750 字进 739 字出），导致 `lastLoaded` 基准对不上、编辑器 change 回声把正文误标"未保存"。

v2 改为：**围栏不进正文编辑器**——文档面板装载时用 `splitBody` 把题记摘出来交给 `<Epigraph>` 渲染，保存时 `joinBody` 接回；编辑题记走悬停 ✎ + 小弹层改围栏原文。**这与 v1 的"编辑态按渲染形态显示、点开才编辑"是同一个交互，但绕开了引擎往返**，是**刻意的改进**。

### 5.5.4 v1 编辑器的坑（v2 换引擎后要重新验证）

1. `lastLoaded` 基准必须存**替换后实际序列化出来的样子**（不是传进去的原文）——否则 change 回声触发整篇重替换、光标弹走、后续按键全丢。
2. 增量替换流式帧时：**删除集不能为空**（BlockNote 源码取 `t[0].id` 会炸）、**纯追加走 insert**、**不能整篇重建**（会把所有动画重播）。
3. Milkdown 必带 `clipboard`（粘贴按 markdown 解析）/ `history`（Ctrl+Z）/ `listener`（markdown 同步给宿主）——缺一个都会表现成"编辑器少块功能"（v2 已带，见 `editor/MarkdownEditor.tsx`）。

## 6. 视觉纪律（VISUAL_SPEC v2，重写）

沿承 v1 的**原则**，换掉它的 Semi 专属部分：

1. 颜色**只用 AntD token**（`token.colorPrimary` 等），**禁止新增 hex**。
2. **紫色仍然只给 AI**（AI 入口、AI 面板内部、草稿流式条、思考行）——这是产品的身份识别，不随框架变。
3. **不反向覆盖 `.ant-*` 内部 class**（v1 对 `.semi-*` 的同款禁令）；确有必要时只允许 top-level 作用域化的例外并写进文档。
4. **单文件 ≤300 行**（v1 违反得最凶的是 `AiPanel.tsx` 962 行、`index.css` 3730 行；v2 不允许全局大样式表——用 token + CSS Modules）。
5. 验收必须**真跑**：无头浏览器截图 + 行为断言，不许只凭"构建通过"。

## 7. 测试基建（v1 为零，v2 必须补）

- **vitest**：纯逻辑——事件归约（`response.* → 会话模型`）、大纲拼接（分章替换）、落位与匹配规则、失效/重挂的状态机。
- **playwright**：真跑主链——`扫描 → 建档 → 写正文（流式）→ 定稿 → 反哺 → 手动制造失效 → 重挂`，每步断言 UI 与服务端状态。
- **lint** = `eslint` + `tsc --noEmit`（v1 的 `lint` 只是 `tsc -b`，等于没 lint）。
