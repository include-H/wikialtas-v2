# v2 技能（Skill）目录

**机制、写法规范、校验方式见 `docs/skills.md`。** 这里只有三件事：L0 目录（= 各技能 frontmatter 的真身）· 基准语料说明 · 进度。

三条铁律（详版在 `docs/skills.md`）：

1. **L0 常驻 = 各技能的 frontmatter**（下面这份清单）。正文**不进 prompt**。
2. **正文按需**：模型判断"我要做这件事"后调 `read_skill(name)`；`/skill <name>` 由用户显式指定，可覆盖模型选择。
3. **触发由任务决定，不由页面决定**。`何时不用` 与 `何时用` 一样重要——它防误触发。

## L0 目录

```yaml
# 写正文
- name: wiki-write
  description: 写或改正文的总纲：判定交付物（载体条目/系列主文/合集/专题）与模式（完整建档/增量编辑）· 开写前要确认什么 · 六条硬规则
  when: 写整篇、或整篇级的改动时，先读这一份（**只改一段 / 只写一个块（如题记）走对应专岗，不必回这里**）
  when_not: 纯问答、只查库、只改结构（建关系/挂链）时不要读

- name: wiki-skeleton
  description: 章节骨架、章名按介质替换（影视=叙事与影像特色 / 图书=创作特色 / 游戏=玩法与结构特色）、小节编号、字段行、排版
  when: 写整篇、或重排章节结构时
  when_not: 只改某一段措辞、只补一个字段值时不要读（那属于修订，走 revise）

- name: epigraph
  description: 题记怎么写：先找材料（台词/歌词/诗/原文）、再定写法（引用/场景/诗句）、署名、剩余名句的去处、禁区
  when: 正在写或改 `:::epigraph` 块时
  when_not: 正文其它部分都不要读（题记通篇只写一次）

- name: prose-style
  description: 文风准则：每句落到具体对象 · 禁套话与空泛赞美 · 事实推断评价分开，附改前→改后对照
  when: 任何写或改正文的文风收尾（含从零写整篇）——通常在末段读；或用户说"读起来像 AI 写的"时
  when_not: 只补结构、只搬事实时不要读

- name: fact-check
  description: 写事实（字段值、剧情节点、评分票房）时怎么核：来源分层 · 三档强度 · 缺口三处理 · 事实账本
  when: 要写字段值、剧情节点、评分票房这类事实时
  when_not: 只做结构调整、只写纯主观概述时不要读；**索引层字段（别名 / 标签 / 关系 / 介质）见 `index-fields`**

- name: multi-source
  description: 同一段故事被多部作品讲过时怎么写：先划本作边界 · 两边都写并标出处 · 跨作品问答要连带
  when: 目标作品与兄弟条目**讲述同一段故事**时（同源改编 / 另一结局 / 后传接着讲同一段）——只是"同一系列"不算
  when_not: 孤立作品、只是查资料/问答不涉及跨作品差异时不要读

# 按介质（一次只读一个）
- name: media-game
  description: 游戏条目的介质差异：章名替换 · 四类标签不串维度 · 版本与 DLC 的区分 · 玩法章怎么写
  when: 正在写或改**一部介质为 game 的条目**时（只是"目标节点是游戏"不算触发）
  when_not: 非游戏介质不要读（读 media-video / media-book）

- name: media-video
  description: 影视条目的介质差异：章名替换 · 一篇覆盖到哪 · 版本边界 · 非线性叙事 · 影像分析怎么写
  when: 正在写或改**一部介质为影视（movie / tv，含动画、OVA/OAD、剧场版）的条目**时
  when_not: 非影视介质不要读（读 media-game / media-book）

- name: media-book
  description: 图书（漫画/小说）条目的介质差异：先判体裁与形态 · 卷册字段与 ISBN · 2.5 分卷一览的表格形态 · 分镜与文体分析
  when: 正在写或改**一部介质为图书（漫画 / 小说）的条目**时
  when_not: 非图书介质不要读（读 media-game / media-video）

- name: series-main
  description: 系列主文与合集条目：先判层级（IP / 子系列 / 合集）· 两个骨架模板 · 同一事实只在一层展开 · 计划状态的五态
  when: 目标节点 kind 是 series / universe，或任务要求把多代作品合写一篇
  when_not: 写一部具体作品时不要读（走 wiki-skeleton + media-*）

# 结构字段（不是正文）
- name: index-fields
  description: 正文之外的索引层字段怎么写：一个条目一个介质 · 别名只收指向本对象的名称 · 关系要具体且方向按工具契约 · 结构动作不夹在润色里
  when: 任务要求写或改别名、标签、关系、介质这类字段时
  when_not: 只写正文时不要读；关系方向语义在工具描述里，这里只管判断

# 非写作任务
- name: analyze
  description: 进料分析：这条是什么 · 与库里哪些节点有关 · 与现有内容矛不矛盾 · 建议怎么建（产出结构化结论，不动库）
  when: 分析一条库条目或一个待建档对象时（含还没建档的条目）
  when_not: 不要用它写正文（那是 wiki-write）；也不要用它替代写正文前的资料收集

- name: qa
  description: 问答：只据库内容回答 · 引用到节点 · 库里没有就说没有 · 好答案可存成"资料"（不改正文）
  when: 用户就库内容提问时
  when_not: 要写或改正文时不要读（走 wiki-write / revise）

- name: revise
  description: 修订：只动指定范围 · 输出只含替换的 Markdown · 给理由 · 新增事实走事实核查
  when: 用户要求改已有正文的某一部分时
  when_not: 整篇重写或从零建档走 wiki-write（不是修订）
```

## 基准语料（`samples/`）

18 篇成品按三组放在 `skills/samples/`（`游戏/` 6 · `影视/` 6 · `书籍/` 6），既是**"写得好"的定义**，也是模型可按需读取的范例库：

- 技能里写 `sample:<文件名>` 是让模型**只读相关的那一节**（例：写题记只读题记块），**不要整篇照抄**。**只写文件名**——加载器在 `skills/samples/**` 里按文件名递归找，所以分组不影响引用。
- 它们**不是**当前要写的作品——作品名、日期、人物都无关，别把内容带进正文。
- **不许改**：发现某处不达标 → 先讨论，记进 `docs/skills.md` 的待定。

## 已做的修正（都是拿语料交叉核对时发现的）

1. **骨架的章名是三档不是两档**：影视「叙事与影像特色」/ 图书「创作特色」/ 游戏「玩法与结构特色」——已修。
2. **`epigraph` 署名格式**：`现代战争` 的「——麦克米兰上尉」证明"引本作可省《作品名》"，原来写死了作品名——已修（引别作仍必须写清）。
3. **2.5 分卷一览的形态归属**：表格四列 + 每卷简介那套落在 `media-book` §5，骨架里只点一句指过去——已修。
4. **题记的双语排布**：原来 `epigraph` 写了"也可整段引出（段间空行）"，于是出现"原文一整段 + 中文一整段"。已删掉这个等价选项，改成**强制逐行交替**（一行原文 + 该行的中文），自检加一条。
5. **样本集扩到 18 篇**（三组各 6）：新写 9 篇 + 重写 1 篇（`上古卷轴V`），10 篇过机械门后归位；旧版《上古卷轴》留在 `_retired-samples/`。

## 已定（避免后来的文档跟现实脱节）

1. **署名行**（引用式）保留为**质量门硬项**，并写明"能查到是谁说的就必须补"。基准里某篇丢署名是那篇的小败笔——**这条记录只在维护者文档里，不进技能**（技能里说基准的坏话会让规则自相矛盾）。
2. **新增可选章「名台词与名场面」**（用户要求）：题记只挑一处点睛，其余名句/名场面收在这一章。设计成**可选**是为了让当时的 6 篇基准仍然满足骨架规则（对齐不破）。
3. **基准语料进运行时**（`skills/samples/`），技能用 `sample:` 引用——这样"示范"才有东西可指（详见 `docs/skills.md` §1、§3.8）。
4. **v1 `frontmatter.md` 按"机械项 vs 判断"拆两处**：
   - **关系方向语义表** → **代码层**（`docs/database.md` §2.1：PG 枚举 + 工具描述，一处定义）；自指由 `CHECK` 挡、悬空由外键挡、成环由应用层查。
   - **判断类**（别名只收指向本对象的名称、关系要具体、结构动作不夹在润色里）→ 新技能 **`index-fields`**。
