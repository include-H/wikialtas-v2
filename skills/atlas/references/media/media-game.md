# 游戏介质

骨架与字段行格式见 `wiki-skeleton`；题记 / 文风 / 事实核查各自独立。**这里只写游戏特有的部分。**

## 1. 本篇用的章名

- 第 3 章 = **世界观与背景设定**
- 第 5 章 = **玩法与结构特色**
- 第 6 章 = **主要角色与势力**，末节固定关系简述（可写 `势力关系简述`）
- 2.2：有 DLC 或资料片时写 `版本与 DLC 关系`；完全没有附加内容就用 `版本关系`，或**整节删掉重排**

## 2. 标签分四类，不要串维度

| 类 | 是什么 | 例 |
|---|---|---|
| **题材** | 大体属于什么 | 角色扮演、动作、策略、视觉小说 |
| **子类型** | 玩法或结构的细分 | 动作角色扮演、第一人称射击、即时战略、回合制、卡牌构筑、章节式冒险 |
| **视角** | 玩家主要用什么镜头看世界 | 第一人称、第三人称、俯视、横版、等角 |
| **内容属性** | 叙事主题或表现气质 | 校园、悬疑、科幻、黑暗奇幻、恋爱、历史 |

```
- 题材：角色扮演
- 子类型：动作角色扮演、章节式冒险
- 视角：第三人称
- 内容属性：黑暗奇幻、神话改写
- 游戏模式：单人
```

**单人 / 多人 / 合作 / 竞技属于「游戏模式」，不是视角。** 标签要短、可拆分、能独立看懂；不要把一整句宣传语拆成词堆进字段，也不要把引擎名或画面技术写成视角。

## 3. 2.1 字段清单

原名、中文名、港台译名、常见简称、制作地区、开发商、发行商、导演或游戏总监、制作人、首发平台、发售日期、游戏模式、题材、子类型、视角、内容属性、引擎（有可靠来源才写）、系列定位、关联前作或续作、主要奖项、分级或内容提示。

**平台移植、区域发售日期差异、版本差异集中写在 2.2**，不要塞进 2.1 的字段值。

## 4. 第 3 章：写"世界怎么运转"

交代时代、地点、社会结构或世界规则、核心冲突，以及**玩家角色在这个结构里的位置**。

- 战争题材：写冲突格局与各方立场；幻想题材：写规则、势力与神话；科幻题材：写技术及其社会后果。
- **这一章不复述剧情，也不用结局解释主题。**

## 5. 第 5 章：写"玩家实际怎么行动"

按作品取舍这些维度：关卡 / 地图结构、任务编排与探索路径；核心战斗、潜行、驾驶、经营或解谜循环；角色成长、装备、资源与难度；叙事与玩法的结合（分支、时间循环、调查、对话选择）；多人 / 合作 / 竞技等附加模式的独立规则；相比同系列前作新增、删减或转向的机制。

每节给 **机制名 + 运行方式 + 玩家感受到的结果**：

- ❌ 战斗系统丰富，操作流畅，自由度极高。
- ✅ 潜行被发现后不直接失败，而是进入 15 秒搜索阶段，玩家可以反打、逃脱或改道；这让「被发现」变成节奏切换，而不是重开存档。

机制名与数值**只有在来源或可复核的游戏内材料支持时才写**。

## 6. 第 4 章：按可解释的推进单位分节

按主线阶段 / 章节 / 阵营线 / 任务弧分节，小节标题点出该阶段发生了什么。**不要逐关复述任务目标清单**；需要列任务时先给阶段概括，再保留少量能说明结构的节点。

多结局或分支：先说明有哪些线、分歧点在哪，再分别写各线走向与收束，并说明哪条是官方正史（**有依据才写**）。

## 7. 第 6 章：角色 + 势力

先写读者必须认识的角色，再写支撑冲突的势力、组织、家族或阵营。每条 1–2 句写**身份 + 作用**；角色多时按阵营或功能分组。行格式全篇统一：一般 `角色名：说明`；有值得列的配音 / 演出阵容时 `角色名（演员 饰）：说明`。

末节用一小段串起 2–3 条关键关系链，把角色表接回剧情。（同一段故事被别的作品讲过时怎么办，见 `multi-source`。）

## 8. 2.2 要区分清楚的东西

| 一组概念 | 判定 |
|---|---|
| 原版 / 加强版 / 导演剪辑版 / 高清复刻 / 重制 / 重启 | 改了故事、关卡、系统或发行身份就说明**具体差异**；重启另立条目 |
| 本体 / 独立资料片 / 扩展包 / DLC / 季票 / 合集 | 说明是否**需要本体**、是否改变主线、内容量级 |
| **合集产品**（把之前几代打包装成一个产品，如《光环：士官长合集》） | 它**是一个有独立发行身份的产品**（按载体条目写），不是"再发行"：2.2 写清 ① 它包含哪几代、② 各代做了什么改动（重制 / 分辨率 / 新增模式）、③ 哪些代是合集独占的；第 4 章**按代次分节**（每代小节写该代主线与落点，不把 N 代写成 N 篇完整剧情，见 `series-main` §4 的合集写法） |
| 跨平台移植 / 区域版本 / 云版本 | **不是新作**，只写平台与日期差异 |
| 只改分辨率、语言、打包方式的再发行 | **不是新作**，一行带过 |

同名作品会混淆时，显示名加年份或版本限定。

## 9. 失败路径（On Failure）

- **拿不准是"重制"还是"加强版"** → 查发行方的说法；查不到就按 §8 写清"改了哪些、没改哪些"，**不要**用"重制"当笼统标签。
- **拿不准介质**（同名有动画版 / 漫画版 / 游戏）→ 按本条目要覆盖的那一版写，其它版本只进 2.2；判不出就先确认。
- **标签拿不准** → 宁可少写一个，不要串维度（**视角写成游戏模式是最常见的错**）。
- **机制名或数值查不到** → 按 `fact-check` 处理（`待核实` 或删），不要凭印象写。

## 10. 自检（每项不通过 → 回哪一步）

1. 四类标签互不串维度，游戏模式没被写成视角？→ 有：回 §2。
2. 版本 / 资料片 / DLC / 移植没有混写？→ 混了：回 §8。
3. 世界观、玩法、剧情、评价四章各自承担不同信息，没有互相复述？→ 有：回 §4–§7。
4. 剧情按阶段组织，结局与分支按剧透要求写清？→ 没有：回 §6。
5. 第 6 章没有退化成完整角色图鉴，势力有定位？→ 没有：回 §7。
6. 机制名、数值、平台发售日期、奖项都过了对应强度的核查？→ 没有：回 `fact-check`。
7. 兄弟载体（改编影视 / 漫画 / 小说）只在 2.2 留了接口？→ 没有：回 §8。
