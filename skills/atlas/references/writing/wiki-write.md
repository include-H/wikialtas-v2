# 写正文之前

## 1. 先判两件事：交付物 + 模式

**交付物**（判错会让整篇结构错）：

| 交付物 | 对象 | 接着读 |
|---|---|---|
| **载体条目** | 一部具体作品（一款游戏、一部剧 / 动画、一部电影、一部漫画 / 小说） | `wiki-skeleton` + **一个** `media-*` |
| **系列主文** | 一个 IP、子系列、企划、作者作品群 | `series-main` |
| **合集条目** | 同一系列的多代编号作品、用户要求合写一篇（不逐代建档） | `wiki-skeleton` + 一个 `media-*` + `series-main` |
| **专题资料** | 时代、技术、创作史这类跨作品主题 | `fact-check` + `prose-style`（**不套骨架**） |

**模式**：

| 模式 | 包含 | 规则 |
|---|---|---|
| **完整建档** | 从零写一篇完整条目 | 套骨架、补齐章节、受体量参考线约束 |
| **增量编辑** | 续写、补段、重写、压缩、润色、局部校订 | **不套骨架、不补齐缺章、不追求整篇体量**；只读目标段与相邻上下文；**输出只含新增或替换的 Markdown**，不复述整篇 |

> 增量编辑时**只读与"事实边界 / 当前章节"有关的规则**，不要把整份骨架当提示词塞进来。

## 2. 开写前必须确认的四件事（由表单给，不要自己在对话里问）

1. **交付物与目标**：哪一部 / 哪一层级。
2. **对象边界**：具体到哪一部、哪一季；重制、特别篇、资料片、剧场版、合集**算不算进来**。
3. **剧透**：**默认完整剧透（写到结局）**；只有明确要求无剧透时才收敛。
4. **深度**：完整条目 / 只补某几章 / 只要概览。

**确认不到就别动笔**——尤其"边界"，它决定整篇写哪些、不写哪些。确认结果写进正文开头的 `>` 说明行。

## 3. 通用流程（顺序不能倒）

1. 判交付物 + 模式（§1），确认四件事（§2）。
2. 读需要的规则（§1 表），**不要多读**。
3. **先列事实域与待查问题，再检索核对**——**不要边写边凭记忆补**。
4. **先写结构化事实与剧情，再写题记、评价与连接句。**
5. 按各技能的自检收尾（`wiki-skeleton` / `prose-style` / `fact-check`）。

## 4. 六条硬规则

1. **只写任务指定的那一部作品、那一个层级。** 不顺手创建、修改或补全别的条目、关系或对象（**建档与挂链是人的动作**）。
2. **事实、推断、评价分开写**：事实有来源；推断写明是推断；评价放在有证据的段落。
3. **查不到就写 `待核实`。** 绝不编造台词、日期、数字、奖项、ISBN、出处，也不用「据说」「广受好评」遮盖缺口。
4. **没有检索工具、或检索失败时，不凭记忆填事实**（细则见 `fact-check`）。
5. **正文默认完整剧透**（写到结局）。
6. **不从 skill 名、目录名、样例文件名推断当前写的是哪部作品、有哪些事实。** `sample:` 是范例，不是当前目标。

## 5. 失败路径（On Failure）

- **交付物判不准**（拿不准是载体条目还是系列主文 / 合集）→ **先确认再写**；判错的代价是整篇结构错。
- **边界不清**（重制 / 剧场版算不算）→ 同上，确认后再动笔。
- **材料不足** → 按 `fact-check` 的缺口三处理（写值 / `待核实` / 删行），并把"缺什么"列进交付说明；**不要**靠扩写凑量。
- **发现任务其实是增量编辑** → 切到增量模式（§1），**不要顺手补齐整篇**。

## 6. 自检（每项不通过 → 回哪一步）

1. 交付物判对了？（对象是不是"一部具体作品"）→ 不确定：回 §2 确认。
2. 模式判对了？（是在补一段，还是从零建整篇）→ 不确定：回 §1。
3. 四件事都确认了？→ 漏了：回 §2。
4. 有没有顺手动别的条目 / 关系 / 外部系统？→ 有：删掉，回 §4.1。
5. 事实是"先查后写"的吗？→ 不是：回 §3.3。
6. 有没有从 `sample:` 里搬来作品名 / 日期 / 评分？→ 有：删掉，回 §4.6。
