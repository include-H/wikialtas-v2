# 事实核查

**判断顺序：先看来源是谁 → 再看这条事实属于哪档 → 最后看查不到怎么办。**

三条分开写，不要混：**事实**要有来源；**推断**写明是推断；**评价**放在有证据的段落。

## 1. 来源分层（看来源是谁）

| 层级 | 能支撑什么 | 典型 |
|---|---|---|
| **一手 / 官方** | 身份、日期、主创、版本、官方设定 | 官网、发行方或出版社页面、原作文本、官方商店页、颁奖机构公告 |
| **专业数据库 / 权威媒体** | 交叉核对、补结构、评分与商业数据 | 综合百科、作品数据库、行业统计站、专业媒体报道 |
| **社区与自媒体** | **只能当线索**（用来知道该去查什么），**不能单独支撑任何关键断言** | 论坛帖、解说视频、粉丝站、影评书评 |

- 「两条独立来源」指**信息链路独立**：同一内容的不同语言版本、互相转载的站点、抓同一个数据库的页面，都只算一条。
- 选来源要它**覆盖这部作品所在的市场与语区**——别漏掉更权威的官方来源。

## 2. 三档强度（看这条事实属于哪档）

| 档 | 什么 | 强度 |
|---|---|---|
| **身份类** | 作品名、主创、首发日期、平台、集数或卷数、版本关系 | 至少一个权威出处；关键项再找一条独立来源交叉确认 |
| **细粒度类** | 逐字台词、事件归到第几集/卷/场、各种计数、人物亲属关系、逐卷卷名与 ISBN | 写完后**逐条**回原始材料核对，**不能抽样** |
| **数字与时间点** | 评分、票房、销量、奖项、「截至某日」的现状 | 记**统计口径 + 检索时间**；来源冲突就继续查，查不动则**并列争议**或标 `待核实` |

**冲突值的默认路径**：字段里写**单一值得信口径**（字段的值里只有值）；**并列争议写进正文**（评价章或 `>` 说明行），不要塞进字段。**检索时间统一写在 `>` 说明行**，不逐条进字段。

## 3. 缺口的三种合法处理（看查不到怎么办）

| 情况 | 做法 |
|---|---|
| 查到了 | 写值，且**能回到来源** |
| 查不到，但字段对读者重要（发行日期、卷数、集数、ISBN、导演、作者） | 值写 `待核实`——**就这三个字**，不加括号、不换说法 |
| 查不到，且字段本可省（引擎、奖项、别名、插画） | **整行删掉** |

**禁止**：编造；按相近版本套用；用「据说」「据报道」「相传」「一般认为」「广受好评」把缺口糊过去。

## 4. 事实账本（产出物）

全程维护一张表，**交付时可以附上**：

```
Input:  待写的断言清单（字段值 / 剧情节点 / 数字）
Output: 账本 —— 每条：断言 | 来源 | 状态
        状态 ∈ 已核实 / 冲突 / 待核实
        另附：未解决的冲突清单 + 待核实清单
```

## 5. 剧情章的事实

先用**官方简介、原作文本、节目资料或作品内文本建立事件链**，再写概括（顺序不能倒）。
没有来源支持的动机、动作、对白 → **删掉或降级成「未说明」**。

## 6. 失败路径（On Failure）

- **没有检索工具 / 检索失败 / 结果不可用** → **不要凭记忆填事实**：
  结构照写（不依赖检索）；需要来源的具体值一律 `待核实`；在 `>` 说明行写明「本篇未联网核实」并列出待核实清单；**题记退回场景式**（细则在 `epigraph` 的失败路径里）。
- **来源冲突** → 继续查；查不动 → **并列争议**，或标 `待核实`。
- **只拿到大意**（拿不到原始语言 / 原文） → 按缺口处理，**不要"补全"**。
- **拿不准某个值** → 宁可 `待核实`：**错误的具体数字比空缺更难被发现和修正**。

## 7. 题记引文是例外

题记的核实门槛是「**能指到出处**」（允许译文 / 语种 / 表记差异），**不走**"逐字台词"这一档——那套细则在 `epigraph` 里。

## 8. 自检（每项不通过 → 回哪一步）

1. 每条关键断言都能指到来源？→ 不能：回 §1 补来源，或按 §3 处理缺口。
2. 细粒度事实**逐条**核过（不是抽样）？→ 没有：回 §2。
3. 数字带**统计口径 + 检索时间**？→ 缺：回 §2。
4. 缺口只有 `待核实` 或整行删除，没有被糊过去的？→ 不是：回 §3。
5. 无检索能力时，写清了「未联网核实」+ 待核实清单？→ 没有：回 §6。
6. 事实 / 推断 / 评价三者分开了？→ 混了：把推断改成「未说明」或删掉。
