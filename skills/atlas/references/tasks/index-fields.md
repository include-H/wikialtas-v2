# 索引层字段

**字段是正文之外的索引层**：它承载**身份、检索、关系**，**不承载剧情、评分、ISBN、发行日期**（那些写在正文对应章节）。
**字段也不能反过来决定文章写什么**——先定内容范围，再补字段。

## 1. 一个条目一个介质

`medium` 只有一个值。**同一个 IP 的不同载体是不同条目**，不是一条挂多个介质（游戏版、动画版、漫画版并存时，各自一篇）。

## 2. 别名：只收"真的指向本对象"的名称

- **收**：正式译名、港台译名、常见简称、原名。
- **不收**：兄弟载体或其它作品的名字——**那会让检索把两个对象混成一个**。这是最常见、也最贵的错。
- 别名同样**要有来源**；不确定就留空或写 `待核实`，不要用肯定语气掩盖。

## 3. 关系：一条边只描述一个事实

- 每条只描述**两个明确对象之间的一个关系**；
- **不要用模糊的「相关」代替具体关系**；
- **不要为了让关系图好看而猜关系**；
- 禁止**自指、成环、指向不存在的对象**；
- 目标对象必须**唯一可识别**；识别不了就**报告悬空目标**，**不要顺手创建新对象**。

**方向与关系词以工具契约为准**（`upsert_relation` 的 description 里写死了方向语义：改编作 → 原作、续作 → 前作…）。**按契约填，不要自己发明方向或新关系词。**

## 4. 边界

- 不把**外部页面 URL、文件路径、临时 ID、某个应用的内部状态**写成字段。
- **别名与关系的增删改是独立的结构动作，不能夹在正文润色里悄悄带过**（与 `wiki-write` 硬规则 1 同源：只动任务指定的对象）。
- 新增字段名、枚举值或关系词之前**先看工具契约与枚举**；冲突时以契约为准。

## 5. 失败路径（On Failure）

- **关系方向拿不准** → 查工具描述里的方向语义表；**不要**两向都写，也不要写"互为"。
- **对象识别不了**（同名、指代不清）→ 报告「目标不唯一 / 悬空」，**不新建对象**。
- **别名拿不准是不是指向本对象** → 留空或 `待核实`；**宁可少收，不要误合并**。
- **任务只要求改正文，但发现字段该改** → **不要顺手改**；在交付说明里提出（结构动作要人确认）。

## 6. 自检（每项不通过 → 回哪一步）

1. 一个条目只有一个 `medium`？兄弟载体没被合进同一条？→ 没有：回 §1。
2. 别名都真的指向本对象？没有把兄弟载体、别的作品的名字收进来？→ 有：回 §2。
3. 每条关系都具体（不是「相关」），方向与契约一致？→ 不是：回 §3。
4. 有没有自指 / 成环 / 指向不存在的对象？→ 有：回 §3。
5. 有没有把 URL / 路径 / 内部状态写成字段？→ 有：回 §4。
6. 结构动作是独立做的，没有夹在润色里？→ 不是：回 §4。
