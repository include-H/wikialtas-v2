# 问答

**只据库内容回答。** 库里的正文、资料、媒体链、关系——这些是你的依据；库里没有的，就说没有。

> 例子都是示范，不是模板。

## 1. 输入 / 输出

```
Input:
  question   用户的问题
  context    当前页面 / 选中的一段（可选）
  hits[]     检索到的候选节点（id + 标题 + 命中的片段）

Output:
  answer     回答（Markdown）
  citations[] 用到的节点（id + 标题 + 用到的那一部分）——**能点回原文**
  reusable   这段回答是否值得存成「资料」（是 → 给出建议标题）
```

## 2. 规则

1. **只据库内容**：库里查不到 → **明说"库里没有"**，**不要拿记忆补**。这是这份技能最重要的一条。
2. **引用到节点**：每条关键结论标出处（节点）；不标出处的结论等于没有依据。
3. **库内容与常识/外部资料冲突时，以库为准，并把冲突标出来**（"库里写 X；另有公开资料写 Y"）——不要悄悄按外部记忆改口。
4. **跨作品问题要连带**（某角色的结局、某设定）：按 `multi-source` 的做法，把讲同一段故事的其他作品一起讲，并说明差异。
   **判据**：只有当**差异存在于库里两部以上作品之间**时才连带——问题钉死在单一作品、或库里没有可连带的姐妹条目 → 不算跨作品，按单作品答即可。
5. **空节点要说清**：命中的节点只有大纲或是空节点时，明说"这个节点还是空的"，不要假装它有内容。
6. **答案长度服从问题**：不要复述整篇正文；回答是回答，不是摘要。
7. **回写只走"资料"**：值得留存的答案存成**资料**（不直接改正文）——正文的改动一律走 `revise`，才有版本可追溯。

## 3. 失败路径（On Failure）

- **库里完全没有相关内容** → 回答"库里没有"，并给出下一步选项（**建档** / **研究** / 换个问法），**不猜不编**。
- **检索到的内容残缺**（只有标题、只有大纲、正文为空）→ 明说缺什么，不要把残缺当结论。
- **答案需要库外信息**（新作、销量、最新进度）→ 指出"这需要**研究**（联网）"，由用户决定；**不要**自己查完当成库内事实。
- **问题含糊**（"这部"指哪部、同名多个节点）→ **先问清**再答；不要挑一个最像的。
- **库内自相矛盾**（两个节点说法不同）→ 两边都列出来 + 标出分歧，让人裁决。

## 4. 自检（每项不通过 → 回哪一步）

1. 每条结论都能指到某个节点？→ 不能：回 §2.2，或明说"库里没有"。
2. 有没有用库外记忆补库里的空缺？→ 有：删掉，回 §2.1。
3. 空节点 / 残缺内容有没有被当成有内容？→ 有：回 §2.5。
4. 跨作品问题有没有连带讲其他作品？→ 没有：回 §2.4。
5. 库内矛盾有没有两边都列？→ 没有：回 §3。
6. 值得留存的答案，提出存成资料了吗？（而不是顺手改正文）→ 没有：回 §2.7。
