# 修订（增量编辑）

**只动指定的那一块。** 修订的价值在于"精确"，不在于"顺便把别处也改好"。

> 例子都是示范，不是模板。

## 1. 输入 / 输出

```
Input:
  target    目标（节点 / 资料）
  scope     范围：某一章（heading）/ 选中的一段 / 全篇的某个方面（如"统一人称"）
  why       为什么改（用户意见 / 体检发现 / 事实修正）

Output:
  patch     替换片段——**只含被替换的 Markdown**，不复述整篇
  reason    改了什么、为什么
  todo[]    这一轮仍不确定、需要核实的项（如有）
```

## 2. 规则

1. **只动指定范围**：不顺手改别处、不重排章节、**不补齐缺失的章节**（那是完整建档）。
2. **输出只含新增或替换的 Markdown**，不要复述整篇正文（复述会让人以为整篇都变了）。
3. **改完保留原有的事实与来源**；**新增的**事实要走 `fact-check`（来源分层 / 缺口三处理）。
4. **用户意见模糊时先定位**（"太啰嗦"→ 是哪一段、哪种啰嗦），再动手；**不要**用整篇重写来蒙对。
5. **涉及结构就不是修订**（拆章、改章节编号、把一节搬去另一章）→ 先确认，那属于结构动作。
6. **改动过大就不是修订**：如果要改的超过原章节的一半，先说清"这其实是重写"，由用户决定走哪条路。
7. 文风问题按 `prose-style` 改；跨度、连带关系按 `multi-source` 处理。

## 3. 失败路径（On Failure）

- **找不到指定章节** → 报「没找到该章节」**并列出实际章节名**，不要挑一个最像的去改。
- **意见无法定位到具体段落** → **先问**，不要整篇重写。
- **需要新事实但没有来源** → 按 `fact-check` 的缺口处理（`待核实` / 删），或说明"缺什么材料"。
- **改完发现影响别处**（同一事实在另一章也有）→ 在 `reason` 里指出，**不要**顺手改另一章（超出范围，需人确认）。
- **用户要的其实是"重写"** → 停手，说清区别，让用户改走 `wiki-write`。

## 4. 自检（每项不通过 → 回哪一步）

1. 输出只含被替换的那一块？（不复述整篇）→ 不是：回 §2.2。
2. 有没有动到范围之外的内容（章节结构、别章、别节点）？→ 有：撤掉，回 §2.1。
3. 新增事实过了 `fact-check`？原有事实与来源有没有被误删？→ 没有：回 §2.3。
4. `reason` 写清了吗（改了什么、为什么）？→ 没有：回 §1。
5. 改动幅度是不是已经不算"修订"了？（超过半章）→ 是：回 §2.6，改走重写。
6. 仍不确定的项，进了 `todo` 而不是被猜成结论？→ 没有：回 §1。
